# 本地训练监控与 CPU 对弈

服务地址为 <http://localhost:8765>，对弈室为 <http://localhost:8765/play>。
默认仅监听本机回环地址；Windows 通过 WSL 的 localhost 转发访问。关闭浏览器不会停止训练。

## 常驻服务与继续训练

监控已由 WSL 的 `siguozero-monitor.service` 托管，异常退出后等待 3 秒重启。
Windows 计划任务 `SiguoZero Monitor` 在当前用户登录时静默启动 WSL 和监控，
已取消任务的默认运行时限。关闭网页或终端后仍可访问监控。

首次安装或重新部署监控，在 WSL Ubuntu-24.04 中执行：

```bash
cd /mnt/e/agent/siguozero
sudo /root/anaconda3/envs/siguozero/bin/python tools/install_monitor_service.py
```

安装器先验证服务配置，再迁移该项目原有的监控进程；不会停止 GPU 训练。
重复安装相同配置时保留当前服务和 CPU 棋局；需要迁移时会检查是否还有未结束的棋局。
当前 WSL 已启用 systemd，安装不需要重启 WSL。

在 Windows PowerShell 注册登录启动任务：

```powershell
& E:\agent\siguozero\scripts\monitor_service_windows.ps1 -Register
```

计划任务执行隐藏的 PowerShell 入口，保持一个前台 WSL 调用，确保监控不依赖终端窗口。
这是因为 [WSL 官方文档](https://learn.microsoft.com/en-us/windows/wsl/systemd)
明确说明 systemd 服务本身不会维持 WSL 实例存活。
登录启动只启动监控；GPU 训练仍通过下面的明确命令启动或接续。

在 WSL Ubuntu-24.04 中，进入 `/mnt/e/agent/siguozero`：

```bash
# 启动/复用监控和对弈服务，不启动或恢复训练
/root/anaconda3/envs/siguozero/bin/python tools/local_console.py

# 明确启动本地四暗棋训练；已有同一任务时返回其 PID，不重复启动
/root/anaconda3/envs/siguozero/bin/python tools/local_console.py --start-training
```

训练配置为 `configs/local_4090_training.yaml`：沿用 96 局、8 个环境进程、
98304 环境步/轮、学习微批 32 的 4090 配置；总预算为 30 亿环境步。
本地配置额外启用每 15 秒资源心跳、每 5 轮对弈快照，以及每轮总计 500 局、半数历史队友的观察评测。
这是本地四暗棋训练，输出到 `runs_local_4090/four_dark/with_dead_rules`。
旧双人训练目录保留原状。

启动器识别并复用已安装的 systemd 服务，检查 HTTP 端口与服务 PID 是否一致。
监控与 CPU 棋局属于同一个 systemd 控制组；GPU 训练在独立进程组中运行。
重启监控不会中断训练，但会结束当前 CPU 棋局。监控崩溃后，其 CPU 子进程也会回收。
若尚未安装服务，启动器仍支持原来的后台进程方式。

服务管理与日志（WSL 中）：

```bash
systemctl status siguozero-monitor.service --no-pager
journalctl -u siguozero-monitor.service -n 50 --no-pager
sudo systemctl restart siguozero-monitor.service
```

训练日志、PID 记录及 Windows 保活入口日志在 `output/local_console/`。
服务每次启动都会原子更新 `service.json`；`/api/health` 返回实际 PID 和管理服务名。
Windows 登录任务状态可用 `Get-ScheduledTask -TaskName 'SiguoZero Monitor'` 查询。
注册的登录入口已手动触发验证；为保持当前训练，没有通过重启电脑验证登录触发。
电脑关机、显式关闭 WSL 会停止当前训练；休眠期间训练暂停，服务不能跨关机保留进程内状态。

如需手动停止训练，先核对 `output/local_console/training-four-dark-local.json`
中的 PID 与命令，再向该 PID 发送 `SIGTERM`。训练器会在完整轮次边界退出。
服务本身不提供修改训练参数、暂停或删除检查点的 HTTP 接口。

## 监控口径

- 进程身份：同时核对 `/proc` 的命令、运行目录、启动时间与心跳 PID，排除 PID 被复用和旧日志误报。
- 存活、心跳过期、初始化、停止、预算完成分别显示。DDP 必须所有 rank 心跳正常才显示健康运行。
- PPO 用 `cumulative/environment_plies`；旧 GRPO 分支预算用 `cumulative/continuation_plies`。
- 完整周期吞吐用本次进程最近至多 7 条指标之间的累计步数差除以时间戳差。
  窗口内的保存、评测、布阵、同步、快照导出均进入分母；重启前的停机时段不混入。
- 轮内吞吐另列，不能代替完整周期吞吐。样本不足两条或进程停止时不展示当前 ETA。
- 20 天所需吞吐为“当前剩余步数 / 20 天”。这不是从首日开始固定的日历期限。
- 3B 步完整预算约需 1736 环境步/秒才能在 20 天内完成。
  之前性能测量外推约 27.3 天，实际工期还受长局、评测、保存与停机影响。
- 指标中的胜/和/负为训练自我对弈统计，不能据此宣称模型棋力提高。

## 胜负与完成局数

每个训练任务的进度条下方展示累计已记录完成局数、胜/和/负、胜率、和棋率，
以及最近一轮的结算数量。展开“最近 12 轮结算记录”可查看每轮战绩和日志累计局数。
页面每 15 秒刷新一次；正在进行中的棋局在终局后所属训练轮完成时进入统计。

- 四暗、双明 PPO 按 **0/2 队视角**统计，一场完整棋局只计一次；不会按四个座位重复计数。
- 若使用双人 PPO，按 0 号席位统计。旧双人 GRPO 的胜负按分支根节点行动方计算，
  页面标为“终局分支”，不能与完整基础棋局数混用。
- 胜率是胜局数除以全部已记录结算局数，分母包含和棋。
- 对阵此前最优模型的选拔评测单独展示轮数、局数、战绩和最近一轮得分率。
  只读取 `model_selection/state.json` 已提交的完整评测报告，不把在途或未提交结果算进去。

训练器已将每轮 `rollout/wins`、`rollout/draws`、`rollout/losses` 等统计写入
各训练目录的 `metrics.jsonl`。监控从完整历史增量建立
`output/local_console/outcomes.sqlite3` 索引，不受损失曲线最近 120 条窗口限制。
索引按运行目录隔离，保存每轮统计和读取位置；监控重启后继续读取新记录。
重复日志不重复计数；断点恢复回退到较早训练轮时，以恢复后的有效训练分支为准。
半行 JSON 等待下次读完后再计数；历史日志被截断或替换时重建索引。

页面的“累计已记录”只包含能从源日志核对的结果。历史不完整或还在回填时，
同时显示已记录数量和日志中的累计数量；缺失的胜负显示为未知，不伪造为零。
索引只是可重建的监控数据，不替代训练检查点；该功能不会重启或修改 GPU 训练。

统计测试：`tests/test_outcome_statistics.py`；前端纯渲染测试：
`node --test tests/test_dashboard_outcomes.cjs`。
实际累计值与完整源日志的核对见
[统计运行证据](benchmarks/outcome_statistics_validation_20260911.json)。

## CPU 对弈与检查点选择

每个棋局启动一个独立 Python 进程，导入 torch 前清空 `CUDA_VISIBLE_DEVICES`，
同时清除分布式 rank 环境变量。模型始终以 `map_location="cpu"` 加载并运行于 CPU；
不加载优化器或 Critic 到设备，不建立 CUDA 上下文。
默认每局 2 个计算线程、最多 2 局，CPU 优先级降低；空闲 30 分钟后释放进程。
推理本身不使用显存，仍会使用本机 CPU 与内存。

界面显示以下权重来源：

1. **固定旧基准（归档）**：本地观察模式迁移时的旧冠军；其他仍筛选模型的配置显示“评测最优”。
2. **最新训练快照**：本地训练开始时、之后每 5 轮原子导出的 Policy/Layout 权重。
3. **最近可恢复检查点**：训练器保存的 `checkpoints/latest.pt`。

本地四暗棋全程只观察评测结果，新打开的对弈页面默认选择最新可用模型，不因评测失利切回旧版本。
前半程固定旧冠军作为基准，15 亿步后使用固定历史对手集。
列表另保留“最近完成评测快照”，便于重现对应评测。手动选定的模型和已经开始的棋局不随新快照改变。
监控展示各旧版本的总分，以及当前队友和历史队友各自的胜负、得分率与区间。每轮共 500 局，队友两种条件各 250 局，评测不设置晋升门槛。训练中的历史队友比例仍为 20%，与评测独立。
更新页面脚本后刷新页面即可读取训练器发布的观察模式指标；可保留旧监控进程及其 CPU 棋局，避免为刷新模型推荐而重启服务。旧进程的直接 `/api/models` 调用仍返回原字段，网页会结合 `/api/status` 选择最新模型；下次正常服务重启后，API 自身也使用新的推荐规则。

未完成评测的初始基线、训练快照和性能实验模型均明确标注。
“最优”仅指本项目该模式、该实验的已完成评测；不代表外部最先进模型。
注册目录在 `configs/local_console.json` 中明确列出，不扫描并混用其他实验。

**旧双人主模型 update 212 是 v4，当前网络需要 v6**。
监控仍展示其历史进度，但对弈选择器禁用此不兼容项。
双明棋当前注册的是 v6 性能实验参考，不能视为经过棋力认证的冠军。
四暗棋新训练快照在初始化后即可选择；第 0 轮为未训练权重。

每局开局时复制参数到 CPU 模型，后续权重发布不改变本局对手。
页面刷新会恢复同一浏览器标签页中的棋局。刷新模型列表并重新开局可读取新版本。
AI 应手按每一步棋盘逐步展示，默认间隔 1 秒，可在“AI 行棋间隔”选择
0.5、1、1.5 或 2 秒，浏览器会记住选择。开局前的 AI 先手、玩家走棋后的连续应手、
出局后的继续观战均使用相同间隔；每一步同步更新棋盘、金色走法连线和行棋记录。
四人对弈中，玩家没有任何可移动走法时立即进入观战，即使仍有跳过次数也不再等待玩家点击。
只能跳过的回合会按现有规则自动处理，仍计入跳过次数和无吃子步数；若后续重新出现可移动走法，
恢复玩家操作。只剩军旗、地雷或被锁在大本营的棋子时，同样自动观战。
已有旧 CPU 棋局刷新页面后也支持自动处理强制跳过，无需结束或重开当前棋局。
玩家席位被扛旗或因无合法行动出局后，会自动继续观战剩余 AI 对局，
直到整局胜负或和棋结算，无需逐轮点击。可用“暂停观战”在当前一轮展示完后暂停，
暂停后可以结束棋局、重新开局或继续观战；刷新页面恢复出局棋局时也会自动续局。
连接异常时自动暂停并保留重试入口。此功能更新后刷新当前对弈页即可使用。
展示期间暂时禁用走棋和开局操作，完成后恢复。等待发生在浏览器，不改变模型采样或训练速度。
已有 CPU 棋局仍运行创建时的代码；更新服务文件后，刷新页面并新开一局即可使用逐步展示，
无需重启监控或中断训练。
支持座位选择、走法高亮、服务器合法性校验、回合版本校验、模型自动应手、
淘汰后继续观战、终局结算，以及仅含玩家可见信息的 JSON 棋谱导出。
进行中的棋盘和普通棋谱通过规则引擎 `observe(human_seat)` 生成，不返回暗棋的隐藏身份。
整局结束后，可通过独立的明棋复盘查看各方真实棋子。

## 上局明棋复盘

刷新对弈页面后，新开的棋局会从初始布阵开始记录复盘。已经运行的旧 CPU 棋局保持原样，
页面会提示下一局才支持明棋复盘；无需重启监控服务或中断训练。

整局胜负或和棋结算后，页面自动保存明棋记录。点击“结束棋局”，或在现有棋局中点击
“开始新棋局”，也会先保存当前记录，再关闭旧对局进程。主动结束的棋局标为“主动结束”，
不虚构胜负。四人棋中，玩家本人出局但队友仍在对局时，不会提前开放本局的隐藏身份。

点击“明棋复盘”即可从初始布阵自动播放，所有席位的棋子均显示真实身份，座位方向与对局时一致。
支持暂停、上一步、下一步、回到初始布阵、跳到最后一步、拖动进度，以及 0.5、1、2、4 倍速。
复盘会还原走棋、吃子、玩家出局和跳过回合，并显示对应行棋记录。
查看上一局期间，当前棋局暂停页面操作；退出复盘后恢复原来的盘面和观战设置。

只保留最近一局明棋记录，存储在当前浏览器、当前服务地址的本地存储中；刷新或新开一局后仍可查看，
下一局结束时替换。清理浏览器数据、切换浏览器或服务地址后，记录不会自动迁移。
复盘时使用“导出棋谱”可另存包含全部棋子身份的 JSON 复盘文件。
若浏览器空间不足，页面会提示导出；本次页面仍可播放，但刷新后可能丢失未保存的记录。

CPU 对局进程私下记录一次初始盘面和每一步发生变化的格子，只有终局或明确结束请求后才返回明棋数据。
浏览器通过这些增量记录还原盘面，播放时不调用模型推理，也不占用 GPU。

专项验证：`tests/test_game_replay.py` 与 `tests/test_local_console.py` 共 19 项 Python 测试通过，
`tests/test_play_spectator.cjs` 共 19 项页面逻辑测试通过，覆盖终局前隐藏身份隔离、完整盘面还原、
主动结束、座位旋转、刷新保留、连续播放、拖动回退，以及查看上一局时保留当前对局。
另用独立端口上的随机 tiny 模型验证实际浏览器中的暗棋对局、主动结束和明棋播放；此验证仅检查功能。

## 对弈快照与断点恢复不同

`runtime.inference_snapshot_every_updates` 默认 0，不改变其他训练配置。
本地配置设为 5；快照写到 `inference/policy_<update>_<generation>.pt`，
先完成文件，再原子发布 `inference/manifest.json`，保留最近三代。
导出复制 Policy/Layout 权重，不更改训练 RNG、参数或优化器。

本地完整检查点采用 **periodic** 策略，每 1000 万环境步保存；正常停止会在当前轮完成后额外保存，每 5000 万步评测前后也会保存。
进度条实色部分表示已完整保存、可恢复的步数，斜纹表示尚未保存的完整轮。异常退出后主进度回到最近完整检查点，重启不会沿用旧日志的更大数字；损失曲线和胜负索引同步过滤被弃置的更新。详见[裁剪与恢复进度](adaptive_clipping_and_resume_zh.md)。
后续每次评测共 500 局：15 亿步前对阵固定旧基准，此后在整个历史对手集间分配；每个完整四局组包含两局当前队友、两局历史队友。所有评测模型快照都会保留，胜负只记录棋力变化；已有 100 局旧协议评测记录保留原样。
**对弈快照不含优化器、Critic 和基础棋局池，不能作为断点恢复文件。**
首轮评测前若训练中断，该目录没有完整 `latest.pt` 时，启动器会拒绝从随机权重悄悄重启。
后续只能从真实存在的完整训练检查点恢复；不要将对弈快照重命名为 `latest.pt`。
