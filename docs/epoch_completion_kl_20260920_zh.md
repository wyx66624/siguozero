# 按 epoch 完成情况控制 KL 与学习率

当前 expand 四暗 MAPPO 使用以下规则，替代原来的 0.08–0.12 保持区间、连续三轮确认及冷却规则。

- Actor 第一遍完整覆盖本批所有学习样本；遍末检查平均 KL。
- 第二、三遍每 16 次 Adam 更新后和遍末，用本轮同一组 8,192 个样本计算当前策略相对采样策略的近似 KL。大于 0.1 时停止剩余 Actor 更新；等于 0.1 不停止。不用单个训练 minibatch 的峰值代替固定探针均值。
- 第二遍没有完整完成（包括第一遍结束便触发停止）：下一轮学习率乘 0.95。
- 三遍全部完成，且最终探针 KL 严格小于 0.08：下一轮学习率乘 1.05。
- 第二遍完整、第三遍部分完成，或者三遍完成但 KL 不小于 0.08：学习率保持。
- 每轮独立判断，不再等待三次确认或冷却；下限 1e-6、上限 1e-4。初次切换保留断点实际使用的学习率，正常续训保留已决定的下一轮学习率。
- Critic 仍训练完整三遍。当前 Critic / Actor 学习率比例保持为 1。

KL 检查不会撤销刚完成的优化更新。每 16 次更新检查一次，因此这是有间隔的早停，不是每一步都满足 KL <= 0.1 的硬约束。保存每遍的实际覆盖比例、优化步骤及终点 KL，也保存中途探针数量和总耗时。

后续上调阈值由 0.09 调整为 0.08，等于 0.08 不上调。调整只改变当前 expand 配置中的 `increase_kl_threshold`，续训保留断点已决定的下一轮学习率；下文较早运行记录中的 0.09 是当时的历史规则。

本次从 update 1980 完整断点恢复，首轮 update 1981 已验证新阈值 0.08：三遍最终 KL=0.098576，Actor/Critic 学习率均保持 1.65502665e-5，正式训练继续运行。29 项定向检查通过，含 0.08 严格边界及旧阈值断点恢复；运行证据见 `output/diagnostics/lr_raise_threshold_008/live_verification.json`。

性能优化保留完整历史、四个 Critic 视角、奖励、模型结构及每轮 98,304 真实动作。CUDA Graph 使用 1024 / 2048 / 3072 / 4096 token 桶，限制填充和常驻显存；更大的 Critic 优化批次按完整历史分块，按样本数加权累加梯度，再执行一次梯度裁剪及 Adam 更新。保存的独立梯度累加器不与 CUDA Graph 的可复用缓冲区混用。Actor 超过单图容量时走动态打包路径，避免重复固定动作头造成的额外开销。无法捕获时仍完整走原有打包路径。中途检查复用同一组探针的选样和分组，只重新计算更新后的网络输出。

`ppo.critic_full_history_batches=true` 将 Critic 同一视角的完整历史标签一起洗牌，再按 2048 个标签切成优化批次，减少同一个历史前缀跨多个 Adam 步重复编码。每个标签每遍仍使用一次，全部四个视角均保留，每轮 Critic 仍有 576 次 Adam 更新。此项会改变 Critic 的批内样本组合，因此不声称与原来的逐 256 标签历史块洗牌得到相同的参数轨迹；Actor 的洗牌方式保留。分块反向的加权梯度等价性另外验证。

固定 KV 的分组注意力内核按每个局面的实际历史长度结束循环，跳过整块无有效 token 的尾部。CUDA Graph 重放仍读取本次元数据，历史窗口长度不变；测试同时覆盖不同长度、零有效查询和重放时长度变化。

连续复用同一图时，用 CUDA event 确认上次 H2D 拷贝已消费锁页主机缓冲区，再重写该缓冲区。此处仅等待拷贝完成，不强制同步整个反向计算。隔离验证覆盖了重复暂存、不同块权重、共享图池及图路径失败后重算；正式优化器仍保留非有限梯度保护。

同一个 Actor 或 Critic 的不同 CUDA Graph 形状复用一组梯度缓冲区，每次重放先在图内清零，再计算本批梯度。分块累加器仍独立保存，未参与损失的参数保留 `grad=None`，避免额外的 AdamW 衰减。形状增加时不再每种形状重复常驻一整份模型梯度；这不改变样本、损失或优化次数。

验证证据存放在 `output/diagnostics/epoch_kl_speed_20260920/`。CPU 相关检查 119 项通过、2 项 CUDA 条件项跳过、21 个子用例通过；GPU 注意力及固定缓存检查 12 项通过、3 个子用例通过；仪表盘 6 项通过；额外的 GPU 梯度复用测试通过，覆盖不同图形状交替、实际 AdamW 更新及未使用参数。正式 16 层模型的分块反向与普通反向对照中，Actor / Critic 梯度相对 L2 误差约 0.56% / 0.43%，处于 BF16 计算差异范围；锁页暂存缓冲区重复使用检查通过。`gpu_shared_gradients.json` 另记录六次完整模型的交替形状对照，梯度差异均小于 0.56%，并验证不同形状的梯度地址确实相同。

实际早停反馈已验证并保存在 `live_initial_rules.json`：update 1255 第三遍完成 1/3 时 KL=0.1010，学习率保持 5e-6；1256 第一遍结束 KL=0.10390，下一轮为 4.75e-6；1257 第二遍完成 58.33% 时 KL=0.10848，下一轮为 4.5125e-6。三轮 Critic 均完整训练三遍。上调分支及 0.09 / 0.1 的严格边界通过定向测试；尚不将测试分支当作真实运行分支。

初始尝试的 8192 token 桶不是最终方案。`before.json` / `after_safe.json` 记录这一中间方案在同一 update 1254 断点强制 3+3 遍的对照；`after.json` 是修复暂存缓冲区复用前被非有限梯度保护中止的隔离试验，不保存正式参数。最终小桶选择依据 `graph_shapes.json`，正式吞吐以恢复后的连续完整周期为准。

`decode_comparison.json` 比较相同输入下的新旧注意力内核：平均历史约 256 / 512 / 828 token 时分别为 0.1602 → 0.0676、0.1259 → 0.1187、0.1961 → 0.1931 毫秒，三组输出逐位相同。这是内核短测，不等于整轮速度提升比例。

又在同一个 update 1262 断点比较采样组织方式，每次仅采集 32,768 个真实动作，随后在更新参数前退出。单组 128 局用时 29.77 秒，两组流水各 64 局用时 27.09 秒，故保留 `pipeline_groups=2`。两次检查点均未修改，参数及优化器均未更新；轨迹因批次采样顺序不同而变化，不能称为逐动作相同的回放。证据为 `collection_g1.json` / `collection_g2.json`。正式训练恢复自已保存的 update 1262，累计 124,059,648 步。

共享梯度缓冲区版本随后从 update 1270 的完整断点正常恢复，累计 124,846,080 个真实环境动作；模型、优化器、RNG 和进行中的棋局均延续。`live_validation.py 1271` 读取真实训练日志核对每轮样本数、Critic 三遍覆盖、下一轮学习率及其实际采用值，并记录连续六个完整周期。吞吐使用“新增真实环境动作 / 相邻轮次完成时间差”，包含轮间写盘、快照等开销，恢复停机与首轮编译不混入热身后的窗口。`target_rate_reached` 单独表示六轮平均是否达到 1300，不能用诊断流程的 `complete` 字段替代。

`resource_comparison.json` 对比不同训练窗口中采样阶段的显存观测。此对照和连续吞吐窗口的棋局、Actor 提前停止位置均不同，属于运行观测，不能将全部速度差异归因于某一项修改。长棋局引起的历史窗口重算以及 Critic 图分块增多，仍会使各轮耗时变化。
