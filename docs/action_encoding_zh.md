# 四国军棋与二人军棋静态动作编码规范

版本：0.2（增加每人四次主动跳过）  
适用棋盘编码版本：`board_encoding_zh.md` 0.2

## 1. 文档目的

本规范定义神经网络训练使用的静态动作列表。它根据棋盘拓扑和军棋固定规则，提前删除无论棋子种类和局面如何都不可能一步完成的 `(from_code, to_code)` 组合，从而减少策略网络的输出维度和动作搜索空间。

本规范同时适用于：

- 四国军棋：129 个棋盘点；
- 二人军棋：60 个棋盘点。

所有动作编码都使用当前行动玩家的主视角。玩家切换后棋盘会旋转到同一规范方向，因此各座位使用完全相同的动作编号表。

## 2. 基本定义

一个移动动作表示为有向二元组：

```text
action = (from_code, to_code)
```

其中：

- `from_code` 是棋子起点编码；
- `to_code` 是移动或攻击的目标点编码；
- 普通移动的起点和终点不能相同；唯一例外 `(0, 0)` 表示主动跳过，不对应棋子移动；
- `(a,b)` 与 `(b,a)` 是两个不同动作。

必须区分以下两个概念：

### 2.1 静态可能动作

如果至少存在一种可移动棋子和一种局面，使该动作能够合法完成，则该动作进入静态动作列表。静态列表只依赖棋盘、道路、铁路和大本营锁定规则，不依赖当前棋子分布。

### 2.2 当前合法动作

当前合法动作还取决于棋子身份、敌我关系、占位、铁路阻挡和行营保护等局面信息。它必须由环境在静态动作列表上继续生成动态合法动作掩码。

静态可能不代表当前合法，但当前合法动作一定属于静态动作列表。

## 3. 静态筛选规则

### 3.1 永远删除的动作

以下动作永远不进入列表：

1. 起点与终点相同且不是跳过 `(0, 0)`；
2. 起点位于大本营；
3. 起点与终点之间既没有一条相邻印制线段，也不属于同一个铁路连通分量。

大本营只禁止作为起点，并不禁止作为终点。棋子可以进入或攻击大本营，但进入后不能再次移动。

### 3.2 相邻线段动作

棋盘上每条相邻印制线段都保留两个移动方向，但大本营出发的方向除外：

```text
u <-> v  =>  (u,v), (v,u)
```

这部分覆盖：

- 公路一步移动；
- 相邻铁路移动；
- 行营与周围八方向印制点之间的移动；
- 进入大本营的移动。

### 3.3 工兵铁路动作

工兵能够在铁路网内转弯。只要两个不同点属于同一个铁路连通分量，就存在一种中间无阻挡的局面，使工兵能够从其中一点一步到达另一点。因此同一铁路连通分量内的全部有向点对都进入静态列表。

普通棋子不能在铁路直角路口换线，但这是棋子身份相关的动态限制，不能据此删除工兵可能使用的动作。

### 3.4 行营动作

行营本身不是铁路点，因此从行营出发时，即使棋子是工兵，也只能到达与该行营直接相邻的印制点。

例如四国主视角中，自己阵地 `(row=2,column=2)` 的行营编码为 `6`：

```text
targets(6) = (0, 1, 2, 5, 7, 10, 11, 12)
```

### 3.5 形式化定义

设：

- `V` 为棋盘点集合；
- `E` 为全部相邻印制线段；
- `H` 为大本营点集合；
- `C₁...Cₙ` 为铁路图的各个连通分量。

静态动作集合为：

```text
A_static = {(0,0)} ∪ {
    (u,v) |
    u ∈ V, v ∈ V, u != v, u ∉ H,
    且 [ {u,v} ∈ E 或 存在 Cᵢ 使 u ∈ Cᵢ 且 v ∈ Cᵢ ]
}
```

## 4. 动作数量

### 4.1 四国军棋

四国棋盘具有：

- 129 个点；
- 8 个大本营；
- 73 个铁路点，且构成一个铁路连通分量；
- `73 × 72 = 5256` 个工兵铁路有向动作；
- 368 个不与上述铁路动作重复、且不是从大本营出发的相邻公路动作。

最终得到：

```text
5256 + 368 + 1 次跳过选项 = 5625 个静态动作
```

完整非原地有向点对共有：

```text
129 × 128 = 16512
```

因此提前删除 `10888` 个永远不可能的动作，占 `65.94%`。

### 4.2 二人军棋

二人棋盘具有：

- 60 个点；
- 4 个大本营；
- 32 个铁路点，且构成一个铁路连通分量；
- `32 × 31 = 992` 个工兵铁路有向动作；
- 184 个不与上述铁路动作重复、且不是从大本营出发的相邻公路动作。

最终得到：

```text
992 + 184 + 1 次跳过选项 = 1177 个静态动作
```

完整非原地有向点对共有 `60 × 59 = 3540` 个，因此提前删除 `2364` 个，占 `66.78%`。

### 4.3 汇总

| 棋盘 | 棋盘点数 | 完整非原地点对 | 静态动作数 | 删除比例 |
|---|---:|---:|---:|---:|
| 四国军棋 | 129 | 16512 | 5625 | 65.94% |
| 二人军棋 | 60 | 3540 | 1177 | 66.78% |

## 5. 稳定动作编号

静态动作首先按 `from_code` 升序排列；起点相同时，再按 `to_code` 升序排列：

```python
actions = tuple(
    (start, end)
    for start in sorted(origin_codes)
    for end in sorted(targets_from(start))
)
```

动作在该元组中的下标就是稳定的联合动作编号：

```text
action_id = index of (from_code, to_code) in actions
```

编号 0 固定为 `(0, 0)`；所有普通移动编号相对旧版顺延 1。棋盘点编号保持不变。生产策略使用起点/终点对，因此旧权重无需重排行。

四国动作编号范围为 `0..5624`，二人动作编号范围为 `0..1176`。

只要规则版本、棋盘拓扑和排序规则不变，同一动作的编号就不会改变。训练数据、模型检查点和推理程序必须使用相同版本的动作列表。

## 6. DeepNash 式两阶段动作头

完整动作可以拆分为：

```text
第一阶段：P(start | observation)
第二阶段：P(destination | observation, start)
```

### 6.1 起点头

永远不能出发的大本营不需要输出槽位：

| 棋盘 | 原始点数 | 压缩起点数 |
|---|---:|---:|
| 四国军棋 | 129 | 121 |
| 二人军棋 | 60 | 56 |

`origin_codes[origin_index]` 保存起点头槽位到棋盘编码的映射。

### 6.2 条件目标头

选定起点后，只输出该起点的静态目标列表。不同起点的目标数量不同，因此可以使用固定最大宽度，并把多余尾槽设为 `-∞`：

| 棋盘 | 原始目标宽度 | 压缩后最大宽度 |
|---|---:|---:|
| 四国军棋 | 129 | 76 |
| 二人军棋 | 60 | 35 |

`destination_slot(start, end)` 把目标点编码映射为当前起点下的目标槽位，`destination_at(start, slot)` 执行反向映射。

固定宽度目标头的掩码顺序为：

1. 超出该起点目标数量的尾槽设为 `-∞`；
2. 对列表内动作执行当前局面的动态合法性判断；
3. 当前不合法的动作同样设为 `-∞`；
4. 对剩余 logits 执行 Softmax。

## 7. 动态合法动作掩码

下列条件不能在静态动作列表中提前删除，必须由环境逐局面判断：

- 起点是否有当前玩家的棋子；
- 棋子是否为不能移动的地雷或军旗；
- 起点、终点和铁路中间点的占位；
- 目标是否为己方或盟友棋子；
- 目标行营是否已有棋子；
- 普通棋子是否在铁路路口转弯；
- 普通棋子是否沿允许的直线或印制弧线行进；
- 工兵铁路路径是否被其他棋子阻挡；
- 当前玩家是否仍在场以及是否轮到其行动；
- 跳过只要求当前玩家剩余次数大于 0，不要求棋盘点 0 存在棋子。用尽四次后，`(0, 0)` 的 logit 被掩码设为负无穷，采样概率为 0。

例如，某个普通兵站可能放置地雷，也可能放置工兵。不能因为地雷在该局面无法移动，就删除这个兵站作为起点的全部静态动作。

## 8. 编码示例

以下示例均采用四国军棋的规范主视角：

| 动作 | 是否进入静态列表 | 原因 |
|---|---|---|
| `(0,127)` | 是 | 两点都在同一铁路网中，工兵可以转弯到达 |
| `(7,120)` | 否 | `7` 不是铁路点，两点也不相邻 |
| `(6,0)` | 是 | 编码 `6` 是行营，`0` 是其相邻点 |
| `(6,120)` | 否 | 行营不能一步进入远处的中央铁路点 |
| `(21,26)` | 是 | 可以从相邻点进入编码 `26` 的大本营 |
| `(26,21)` | 否 | 大本营中的任何棋子都不能移动 |

四国主视角下的大本营编码为：

```text
(26, 28, 56, 58, 86, 88, 116, 118)
```

这些编码的静态目标列表全部为空。

## 9. 程序接口

```python
from junqi import FourPlayerBoard

board = FourPlayerBoard()
space = board.action_space

# 完整、稳定、有向的静态动作列表
assert len(board.actions) == 5625
assert space.action_count == 5625

# 联合动作编号
action_id = space.action_index(0, 127)
assert space.action_at(action_id) == (0, 127)

# 两阶段起点编号
origin_id = space.origin_index(0)
assert space.origin_at(origin_id) == 0

# 选定起点后的目标槽位
destination_id = space.destination_slot(0, 127)
assert space.destination_at(0, destination_id) == 127

# 查询某个起点的全部静态目标
targets = space.targets_from(6)
assert targets == (0, 1, 2, 5, 7, 10, 11, 12)
```

`board.action(from_code, to_code)` 只负责校验二元组表示和点编码范围。若需要确认动作属于静态列表，应调用 `space.contains(...)` 或 `space.action_index(...)`。

## 10. 生成伪代码

```text
targets = 每个点的相邻印制点集合

for component in railway_connected_components:
    for start in component:
        targets[start] += component - {start}

for headquarters in all_headquarters:
    targets[headquarters] = empty

for start in point_code_ascending_order:
    for end in sorted(unique(targets[start])):
        actions.append((start, end))
```

动作列表必须由棋盘拓扑生成，不应手工维护数千个二元组。这样可以避免棋盘线段修改后，文档、程序和训练数据之间出现不一致。

## 11. 实现不变量

实现和训练管线必须保持以下条件：

1. 静态动作不包含原地动作；
2. 静态动作不包含任何大本营起点；
3. 所有相邻线段的允许方向都在列表中；
4. 同一铁路连通分量内的全部非原地有向点对都在列表中；
5. 非铁路、非相邻的点对不在列表中；
6. 动作列表没有重复项，并按 `(from_code,to_code)` 排序；
7. 动作编号与二元组能够双向无损转换；
8. 条件目标槽与目标点编码能够双向无损转换；
9. 四国四个主视角的动作列表完全相同；
10. 二人两个主视角的动作列表完全相同。

上述不变量由 `tests/test_board.py` 自动验证。

模型棋盘输入另含四个剩余跳过次数（0–4），顺序与棋子所属座位一致：自己、相对座位 1、对家、相对座位 3。双人模式后两项填 0。动作历史投影保持六维，跳过编码为 `[0,0,0,0,actor,remaining_draw_plies]`，与无动作的初始状态通过 action-present 标记区分。见 [续训迁移说明](pass_action_zh.md)。
