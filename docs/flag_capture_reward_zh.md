# PPO 夺旗中间奖励

当前 4090 配置的 `ppo.flag_capture_reward` 为 `0.2`。旧配置缺省为 `0.0`。

- 按规则引擎当步的 `flag_captured_owner` 事件计分，每面军旗被扛只触发一次。
- 夺旗方队伍获得 `+0.2`，失旗方队伍获得 `-0.2`，包含队友的军旗。
- 普通吃子、靠近军旗、放弃夺旗、无子可走而出局不额外计分。
- 奖励与该步终局奖励相加。例如夺旗直接获胜，该步夺旗方得到 `1 + 0.2 = 1.2`。
- 对手回合的奖励通过 PPO 的队伍符号及 GAE 传播到己方先前动作；历史模型的回合使用当前学习者的价值视角。不会在后续回合重复补发奖励。
- 若夺旗与步数上限和棋同一步发生，夺旗奖励仍按队伍取正负，和棋惩罚对双方均为负。

该项作用于 PPO 行棋轨迹。布局训练继续使用整局结果；比赛规则、评测胜负统计不受奖励塑形影响。双人 GRPO 路径不读取此 PPO 参数。

## 从已有断点采用新奖励

先正常结束当前轮并保存完整 `latest.pt`，再用原配置、原运行目录恢复，额外指定 `--adopt-flag-capture-reward`。此选项保留模型、优化器、随机数、未结束对局和评测进度，仅对恢复后的新事件计分，并立即保存迁移断点。后续相同配置恢复无需再次指定。奖励不一致且没有迁移选项时会拒绝恢复。

迁移记录保存于 `resolved_config.json` 和完整断点的 `flag_capture_objective_migration` 中。

## 运行核验

每轮指标包含：

- `training/flag_capture_reward`：当前系数。
- `rollout/flag_captures`：本轮实际夺旗事件数，包含终局夺旗。
- `rollout/nonterminal_flag_captures`：其中未立即结束整局的事件数。
- `rollout/flag_capture_reward_abs_sum`：本轮已计入 PPO 轨迹的夺旗奖励绝对值之和；不是双方净和，也不表示棋力。

该改动是否改善实战，需要通过冻结模型、独立对手和未参与训练的夺旗/护旗局面评测确认。
