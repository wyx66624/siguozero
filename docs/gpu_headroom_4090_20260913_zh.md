# RTX 4090 当前资源余量与提速方向

本次只观察正在运行的四暗棋训练，没有暂停训练、改变配置或启动竞争 GPU 的模型。连续约 211 秒采集 209 次设备状态，并统计恢复后的第 1322～1331 轮。训练进程 PID 为 91760。

## 当前是否充分利用显卡

仍有利用率和显存余量，但不能把剩余显存比例直接换算为加速倍数。

| 指标 | 本次观察 |
| --- | --- |
| GPU 利用率 | 平均 38.0%，最高 93% |
| 功耗 | 平均 151 W，最高 339 W，设备限制 450 W |
| 温度 | 45～59°C |
| 功耗、温度限制标志 | 采样期间均未触发 |
| PyTorch 每轮已分配显存峰值的最大值 | 14.49 GiB |
| 1 秒采样观察到的整卡显存峰值 | 16.34 GiB |
| 同一训练进程近期资源日志中的整卡显存峰值 | 16.90 GiB |
| 按 16.90 GiB 峰值计算的剩余显存 | 约 7.08 GiB |

页面顶部 14.5 GB 是查询时的整卡占用，不能当作训练全过程的峰值。PyTorch 已分配张量、分配器保留块、驱动与桌面占用也不是同一口径。

NVIDIA 的 GPU utilization 表示采样期间存在 GPU 内核运行的时间比例，并非峰值 FLOPs 的使用比例；memory utilization 表示显存发生读写的时间比例，也不是精确的带宽饱和度。因此不能用 `100 / 38` 推断还可以加速 2.6 倍。[NVIDIA 指标定义](https://docs.nvidia.com/deploy/nvidia-smi/index.html)

现有 15 秒资源日志也显示，在线采样阶段的 GPU 平均利用率约 26%，策略和 Critic 学习阶段约 40%。这些按阶段的样本较少，只用于定位方向，不是 GPU 时间线分析。

## 时间主要花在哪里

第 1322～1331 轮每轮均采集 98,304 个真实环境动作。阶段时间均值如下：

| 阶段 | 每轮平均耗时 | 占轮内耗时 |
| --- | --- | --- |
| 在线采样 | 34.63 秒 | 46.5% |
| 策略学习 | 15.25 秒 | 20.5% |
| Critic 学习 | 21.29 秒 | 28.6% |
| 布阵学习 | 2.54 秒 | 3.4% |
| 其余轮内开销 | 约 0.80 秒 | 1.1% |
| 合计 | 74.50 秒 | 100% |

在线采样内部包含约 19.61 秒 Actor 推理、12.22 秒环境处理工作及 1.35 秒批量 Critic 推理；它们已包含在采样阶段，不能再加到总时间上。最终学习率 KL 检测约 0.21 秒，也已包含在策略学习中。

策略每轮实际优化次数因 KL 早停而变化，平均约 358 次；Critic 每轮为 576 次。本次窗口不能用来声称与其他配置的训练工作量完全相同。

## 剩余显存可以怎样用

当前 96 局、384 席位的固定 KV 缓存占 **11.73 GiB**，与棋局数近似成正比。两组流水实际每次推理最多约 48 局，观测均值为 47.45。

以下只增加 KV 存储，假定其他成本不变，并以观察到的整卡峰值 16.90 GiB 为基准：

| 并行局数 | 每组推理规模 | 新增 KV | 推算整卡峰值 | 判断 |
| --- | --- | --- | --- | --- |
| 96 | 48 | 0 | 16.90 GiB，已观察 | 当前配置 |
| 128 | 64 | 3.91 GiB | 20.81 GiB | 优先做完整轮 A/B |
| 144 | 72 | 5.87 GiB | 22.77 GiB | 余量偏小 |
| 160 | 80 | 7.82 GiB | 24.72 GiB | 按此估算已超过容量 |
| 192 | 96 | 11.73 GiB | 28.63 GiB | 当前缓存方案无法直接翻倍 |

这些是容量估算，不是已跑通的当前版本测试。额外激活、分配器碎片和 CUDA Graph 缓冲可能继续提高峰值。建议以预留 2～3 GiB 的工程余量为起点，因此当前最有价值的是验证 **96→128 局**。

2026-09-11 的旧版 128 局实验曾观察到约 19.23 GiB 已分配、21.38 GiB 保留显存；旧规则、检查点、采样规模与当前不同，不能用其吞吐宣称当前版本的加速收益。

## 优化优先顺序

1. **96→128 局的采样并行。** 保持一轮 98,304 动作及相同训练工作量，测试每组 48→64 是否提高有效 GPU 批量；同时测长局峰值及完整周期，避免仅采样端变快。
2. **学习端的数据准备和同步。** 当前合并后每个优化器小批平均约 7.85 条历史序列，微批上限已经是 32。直接把上限改成 64 通常不会增加实际批量。应定位小张量处理、CPU 调度与设备同步，再测试覆盖更多整步计算的图执行。
3. **环境和推理之间的流水等待。** 目前已有 8 个规则进程、两组流水；进程数增加不保证等待减少。应围绕组大小和交错时机优化，保持采样策略在整轮内冻结。
4. **缓存分配与长历史处理。** 检查点加载后的图捕获、参数更新后的缓存重建和历史滑窗会影响峰值及后期速度。当前源码的 `empty_cache()` 用于避免大 KV 块碎片和 WDDM 保留显存逐轮上涨，不能直接删除来宣称提速。

BF16、变长 Flash Attention、`torch.compile(default)` 的学习子图、采样 CUDA Graph、融合 AdamW、延后 Critic 推理和两组流水已经接入。无需把重新打开这些功能列为新增收益。策略与 Critic 同时用两个 CUDA stream 的旧实验反而变慢，也不能仅因显存有余量就直接开启。

将优化器小批从 512 改为 1024 与提高微批上限是两件事：前者改变 Adam 更新次数、PPO 小批结构及梯度噪声，需要另行验证学习效果，不能当作计算完全等价的加速。也不应通过减少 epoch 或增加早停次数来冒充执行效率提高。

历史对手在 15 亿步后才进入当前训练；已有实现让冻结模型共享受控 KV 槽，避免再复制整份缓存，但仍需为模型副本、图与额外执行留出余量。

## 距离 20 天还差多少

第 1322～1331 轮相邻记录覆盖 884,736 个动作、687.81 秒，完整周期约 **1,286 动作/秒**。这包含窗口中出现的日志和轻量快照成本。

| 条件 | 按当前速度外推 |
| --- | --- |
| 完整 30 亿步 | 约 27.0 天 |
| 第 1331 轮后剩余 28.69 亿步 | 约 25.8 天 |
| 剩余任务在此后 20 天内完成 | 需要约 29.1% 整体提速 |
| 30 亿步全程按 20 天速度完成 | 需 1,736 动作/秒，约 35.0% 整体提速 |

如果整体实测提速 20%，剩余时间条件外推约 21.5 天；如果提速 30%，约 19.9 天。这是目标敏感度计算，不是已经取得或保证能取得的收益。

该时间窗口没有完整评测、完整模型保存、后半程历史混合及更频繁滑窗的摊销，长期工期仍可能增加。下一步最有价值的实验是同检查点、同环境动作数和实际优化器次数下的 96/128 局完整周期对照。

原始采样、源码哈希与统计口径见 [机器可读诊断结果](benchmarks/gpu_headroom_4090_20260913.json)。本次未修改训练代码与运行配置，训练保持运行。
