# PPO 有界动态学习率

当前本地四暗棋配置将策略学习率限制在 **1e-6～2e-5**。回升和下降都经过实际学习率限幅，基础预热、余弦计划仍然有效；当基础计划低于配置上限时，采用更低的上限。倍率本身也会限幅，避免学习率已经到边界后仍积累隐藏的倍率变化。

## 反馈规则

每个完整 PPO 学习轮只更新一次调度器。使用本轮更新结束后的模型，对已有 rollout 中最多 2048 个学习席位样本重新计算近似 KL 和裁剪比例，参照仍是生成这些动作时保存的 `old_log_prob`。

| 情况 | 行为 |
| --- | --- |
| 最终代表性 KL 高于 0.0225（1.5 倍目标） | 下一轮学习率乘 0.8，限幅后生效 |
| 本轮触发过 KL/clip 早停，或最终裁剪比例高于 0.1 | 清空稳定计数，暂停回升 |
| 最终 KL 和其 EMA 都低于 0.0075，连续稳定 5 轮 | 下一轮学习率乘 1.03，限幅后生效 |
| 正常区间 | 保持倍率，继续基础调度 |
| 调整后的 5 轮冷却期 | 暂停回升；可信的高 KL 仍可降速 |
| 无学习样本或预热尚未结束 | 不回升；无样本不推进 EMA |

EMA 衰减为 0.8。不会因训练前几个小批次 KL 接近零而立即提高学习率，也不会因单个小批次尖峰就永久减半；原有每小批次 KL/clip 早停保护保留。最终近似 KL 是抽样估计，不是全动作分布的精确 KL，更不是棋力评测。

## 配置与恢复

配置位于 `configs/local_4090_training.yaml` 的 `learner.learning_rate`：

```yaml
initial: 0.0001
adaptive: true
minimum: 1.0e-06
maximum: 2.0e-05
increase_factor: 1.03
decrease_factor: 0.8
stable_updates: 5
cooldown_updates: 5
ema_decay: 0.8
probe_samples: 2048
recovery_clip_fraction: 0.1
```

`initial` 是基础计划的峰值；实际值受倍率及 `maximum` 限制。新控制器只用于 PPO；GRPO 保留既有反馈方式。PPO 的 `adaptive: false` 关闭动态反馈与额外检测，仍对实际学习率应用上下限。

完整检查点在 `trainer_state.adaptive_learning_rate` 保存倍率、KL EMA、稳定计数、冷却计数和观测次数。旧检查点缺少这些字段时继承 `policy_lr_scale`，从原有学习率连续开始，稳定计数和 EMA 重新积累。恢复时重新应用当前配置的上下限；非法或非有限状态会报错。应从 `latest.pt` 恢复，网页轻量快照不包含优化器与调度恢复状态。

Critic 保持现有与策略学习率的比例关系，其实际上下限按该比例缩放；当前两者初始学习率相同，因此范围相同。布阵优化器不由本控制器调整。

## 计算与监控

检测只对已有样本引用进行片段抽样，保留连续历史编码的复用，排除冻结席位动作，使用独立随机数生成器，不消耗采样/训练随机序列。使用已有策略模型进行无梯度计算，不加载旧模型，不存储整批旧 logits，不修改模型权重或梯度。各微批次统计在设备上累计，只传输少量标量；跨 rank 按实际学习样本数汇总。

网页展示本轮学习率、下一轮学习率、上下限、最终 KL/EMA、稳定计数、冷却期及调整原因。详细日志另记录 `policy/minibatch_kl_max`、`policy/minibatch_clip_max`、`optimizer/policy_stop_kl`、`optimizer/policy_stop_clip` 和 `timing/lr_probe_seconds`。后者包含样本选择与最终模型检测，可用于核对新增耗时。

阈值与倍率是工程起点，控制器通过测试不代表棋力提高或收敛更快。学习效果仍须在相同环境步预算、冻结对手/队友、完整换位组的评测中验证。

## 本地验证（2026-09-13）

从完整检查点 update 1320 开始，保留原有约 `9.97e-6` 的学习率；选择 `2e-5` 作为当前上限，提供约两倍回升空间，避免直接跳回基础初始值 `1e-4`。这个上限是可配置的工程起点，并非已经测出的最优值。

Python 回归运行 115 项，110 项通过、5 项跳过；最终新增断言后重跑 9 项学习率专项测试，全部通过。页面脚本 33 项测试通过。覆盖上下限反复触发、倍率饱和后反向调整、旧检查点迁移、完整恢复、不同 rank 的样本加权，以及检测不修改权重、梯度或训练随机序列。

RTX 4090 上进行了关闭→开启、开启→关闭两组完整轮诊断：每次从同一检查点恢复，完成 98,304 个环境步、576 次策略优化、576 次 Critic 优化和 1 次布阵优化。为匹配优化工作量，**仅诊断进程关闭 PPO 早停、执行完整三轮 epoch**；正式训练仍保留早停。

| 指标 | 关闭动态反馈 | 开启动态反馈 |
| --- | --- | --- |
| 两次整轮耗时 | 99.12 / 105.46 秒 | 106.90 / 106.66 秒 |
| 平均整轮耗时 | 102.29 秒 | 106.78 秒 |
| 新增最终 KL 检测 | 无 | 0.169 / 0.165 秒 |
| 峰值已分配显存 | 13.892 GiB | 13.892 GiB |

这四次诊断中，开启后的平均整轮耗时高 4.4%，两组分别高 7.8% 和 1.1%；采样和 Critic 等其他阶段也有耗时变化。样本数量不足以将全部差异归因于控制器，不能把单独检测的约 0.17 秒直接当作完整训练的总开销。这不是棋力评测，也未覆盖历史滑窗达到 1000 的情况。原始记录与汇总见 [GPU 诊断结果](benchmarks/adaptive_lr_4090_20260913.json)。
