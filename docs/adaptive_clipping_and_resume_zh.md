# PPO 阶段与优势自适应裁剪、检查点与真实进度

2026-09-13，本地 `configs/local_4090_training.yaml` 的四人 PPO 路径启用本方案。
行棋策略的固定 ±0.2 裁剪改为按优势调整上界，并随已完成的环境步预算平滑收窄。
Critic 的 value clip、布阵 GRPO、GAE、熵反馈、学习率上下限和 KL 早停保持各自原有配置。
其他配置默认关闭自适应裁剪，二人 GRPO 不启用。

## 文献依据与实际实现

借鉴 [ACPO 第 3.2 节，公式 5–6](https://arxiv.org/html/2510.00690v1#S3.SS2) 的
Advantage-Aware Adaptive Clipping：用误差函数将优势映射至有界区间，调整概率比上界。
这里没有采用论文的数据筛选与离策略样本复用课程；**按 1/3、1/2、3/4 预算节点收窄是本项目的工程设计**，不是该论文已经验证的军棋训练结论。

设 `r = π_new(a|s) / π_rollout(a|s)`，`A` 为原有 PPO 在整轮可学习席位上全局归一化后的优势：

```text
q(A) = 0.5 × (1 + erf(A / sqrt(2)))
ε_high(A,p) = clamp(b(p) × (1 + 0.5 × q(A)), 0.10, 0.45)
ε_low(p)    = clamp(l(p), 0.10, 0.45)

L_policy = -mean(min(r × A, clip(r, 1-ε_low, 1+ε_high) × A))
L_total  = L_policy - mean(α_phase × H(π))
```

`p` 用本轮开始时已完成的 `environment_plies / target_environment_plies` 计算，限制在 `[0,1]`。
`l(p)`、`b(p)` 在下表节点间线性插值，避免跨过门槛时突然跳变。大优势经 erf 饱和，不能让边界无限扩大；裁剪界限不参与求导。
沿用原有全轮优势归一化，包含多卡的全局矩统计；不按微批重复归一化，冻结席位和图填充行不进入优势矩统计。
原实现的极小方差分支保留原优势，此时 erf 仍保证有界，但不解释为校准后的优势概率。

| 已完成预算 | 下界偏移 l | 上界基准 b | 概率比下界 | 概率比上界基准～最高 |
|---|---:|---:|---:|---:|
| 0 | 0.25 | 0.30 | 0.75 | 1.30～1.45 |
| 1/3（10 亿步） | 0.20 | 0.25 | 0.80 | 1.25～1.375 |
| 1/2（15 亿步） | 0.18 | 0.20 | 0.82 | 1.20～1.30 |
| 3/4（22.5 亿步） | 0.15 | 0.15 | 0.85 | 1.15～1.225 |
| 1（30 亿步） | 0.10 | 0.10 | 0.90 | 1.10～1.15 |

上界是逐样本计算的：同阶段正优势越大，上界越宽。负优势动作的有效 PPO 裁剪主要由下界控制，不能简单给 `abs(A)` 大的负优势也无限放宽。
这些是重要性采样概率比的裁剪边界，不是动作绝对概率，也不保证每次梯度更新后的全状态 KL 都处于某个范围。

放宽更新空间可能让低概率但正优势的走法获得更大更新，也可能更快强化带噪声的优势。
它**不能保证提升熵或避免局部最优**；开局与后续的自适应熵继续鼓励探索，原有最终策略 KL 检测、早停、梯度范数裁剪及有界学习率继续提供保护。
棋力仍需冻结对手、完整换位组和完整规则的评测验证。

## 计算和显存开销

- 普通 PPO 和 CUDA Graph 共用同一组上界与 surrogate 函数，最终 KL 探针的 clip fraction 也按实际边界计算。
- 优势已经在合并的目标张量中；增加的动态控制量沿用现有 pinned-memory 上传，不增加历史、模型权重或完整动作分布的传输。
- Graph 的控制张量从 4 个标量扩展为 8 个标量。进度和上界变化只更新张量内容，无须重新捕获图。
- `policy/clip_upper_mean` 在 GPU 上按有效样本统计，与已有指标一起回传。界限统计在监控服务中展示。
- 变宽的策略更新可能改变 KL 早停时机和实际 Adam 步数，因此不能用少量逐元素算子的成本推断整体训练速度完全不变。

## 停止后从哪里继续

续训入口仍只加载 `checkpoints/latest.pt`：Policy、Critic、Layout、三个优化器、缩放器、随机状态、累计步数、未完棋局和历史、布阵缓存、探索与学习率控制状态一起恢复。
不从 `latest_metrics.json` 的数字或每 5 轮导出的网页对弈快照恢复。

当前本地保存策略是 `periodic`：

1. **正常停止 / SIGTERM / Ctrl+C**：收到信号后完成当前轮，再额外保存完整状态。所以可以保存到非整数门槛的任意完整轮。
2. **异常退出、强杀、系统故障**：只保留最近完成的完整检查点。之后尚未保存的完整轮以及正在执行的部分轮需重算；PPO 不保存半轮更新现场。
3. **轻量网页快照**：每 5 轮供 CPU 对弈使用，不含完整 Critic、优化器和棋局池，不能完整续训。

本次正常暂停已保存 **update 1370 / 134,676,480 环境步**，并不是退回 1.25 亿步。
保持模型架构和 checkpoint format 9；新裁剪调度使用恢复后的真实步数，不从训练启动时间或旧日志最大值开始。

## 保存频率和监控修复

本地完整检查点改为每 **1000 万环境步**保存。跨过整数门槛后，在这一完整轮末保存；当前一轮 98,304 步，保存计数可以略高于整数门槛。
正常停止仍额外保存，评测前后也仍保存。**500 局评测的每 5000 万步日程没有随之改变。**

监控使用小型 `training_progress.json` 发布本进程实际恢复/完成的计数；它本身不包含模型，不能作为检查点。
检查点 manifest 记录其自身累计计数，并在续训读取真实 payload 后修复可能落后的 sidecar。

- 运行时：实色展示已完整保存的进度，斜纹展示已完成但尚未保存的进度。
- 停止时：主进度按可恢复检查点显示；上次进程未保存的额外步数单独提示，不计入可恢复完成率。
- 重启时：立即采用当前进程恢复的步数，旧日志中更大的计数不再覆盖它。损失曲线和局数/胜负面板也过滤弃置分支，吞吐只计算本进程完整周期。
- 面板展示完整检查点间隔和下一门槛，明确轻量对弈快照不能续训。

保存更频繁会增加磁盘写入，但不会增加训练矩阵计算。本次正常停止的完整保存（含归档）约 **18.6 秒**；若按此前约 1761 环境步/秒作条件估算，每 1000 万步约 95 分钟，保存占比约 0.33%。此前 2500 万步约 0.13%，差约 0.20 个百分点。
这只是当前存档体量和吞吐下的估算；周期保存通常没有额外归档，而后期历史、棋局状态、磁盘负载都可能改变开销。
