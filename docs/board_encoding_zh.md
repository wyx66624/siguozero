# 玩家主视角棋盘与路径编码规范

版本：0.2

## 1. 目标

同一套网络应当能从任意座位训练，而不需要学习“红方在下、蓝方在右”一类绝对颜色偏差。因此每个样本都先旋转到当前观察玩家的主视角：

- 自己永远位于棋盘下方并面向中央。
- 自己阵地永远使用最低的一段连续编码。
- 四国棋盘中的对家永远位于正对面。
- 中央九宫随观察玩家旋转。
- 编码是双射：一个物理点在某个视角下只有一个编码，一个编码也只对应一个物理点。

点位编码只表达位置，不表达棋子身份或可见性。暗棋信息必须放在独立的特征通道中。

## 2. 单个阵地的局部坐标

每个阵地都使用其主人自己的局部坐标 `(row, column)`：

- `row=1`：靠中央的锋线。
- `row=6`：靠玩家的端线。
- `column=1..5`：该阵地主人面向中央时从左到右。

阵地内偏移量为：

```text
offset(row, column) = (row - 1) * 5 + (column - 1)
```

以自己阵地为例：

```text
                         中央
row 1       00 -- 01 -- 02 -- 03 -- 04
row 2       05 -- 06 -- 07 -- 08 -- 09
row 3       10 -- 11 -- 12 -- 13 -- 14
row 4       15 -- 16 -- 17 -- 18 -- 19
row 5       20 -- 21 -- 22 -- 23 -- 24
row 6       25 -- 26 -- 27 -- 28 -- 29
                         自己
```

行营局部坐标为 `(2,2)、(2,4)、(3,3)、(4,2)、(4,4)`；大本营为 `(6,2)、(6,4)`。

## 3. 四国军棋：129 点

### 3.1 编码区间

观察玩家旋转到下方后，各阵地区间为：

| 编码 | 相对阵地 | 含义 |
|---:|---|---|
| `0..29` | `SELF` | 自己 |
| `30..59` | `LEFT_OPPONENT` | 左侧敌家 |
| `60..89` | `PARTNER` | 正对面的盟友 |
| `90..119` | `RIGHT_OPPONENT` | 右侧敌家 |
| `120..128` | `CENTER` | 中央九宫 |

阵地点编码公式：

```text
code = relative_arm * 30 + offset(row, column)
```

其中 `relative_arm` 依次为 0、1、2、3。其他玩家阵地中的 `(row,column)` 仍然采用该阵地主人自己的局部左右，不采用观察者屏幕上的横纵坐标。

### 3.2 中央九宫

中央点在旋转后的观察者视角中按“近到远、左到右”编码：

```text
                     对家
far row          126 -- 127 -- 128
middle row       123 -- 124 -- 125
near row         120 -- 121 -- 122
                     自己
```

中央局部公式同样是行优先：

```text
center_code = 120 + (center_row - 1) * 3 + (center_column - 1)
```

`center_row=1` 最靠近观察者，`center_column=1` 位于观察者左侧。切换观察者时，中央坐标按 90° 的整数倍旋转。

### 3.3 视角变换示例

以物理南方玩家为观察者：

- 南方 `(1,1)` → `0`。
- 西方 `(1,1)` → `30`。
- 北方 `(1,1)` → `60`。
- 东方 `(1,1)` → `90`。
- 中央靠南偏西点 → `120`。

改由西方玩家观察后：

- 西方 `(1,1)` → `0`。
- 北方 `(1,1)` → `30`。
- 东方 `(1,1)` → `60`。
- 南方 `(1,1)` → `90`。
- 原中央靠南偏西点旋转为近右点 → `122`。

## 4. 二人军棋：60 点

| 编码 | 相对阵地 |
|---:|---|
| `0..29` | `SELF` |
| `30..59` | `OPPONENT` |

公式仍为：

```text
code = relative_arm * 30 + offset(row, column)
```

切换观察玩家时，双方阵地区间交换；每个阵地内部继续使用其主人的局部坐标。因此同一个玩家自己的 `(1,1)` 在其本人视角下始终是 `0`。

## 5. 路径二元组

### 5.1 底层棋盘线段

棋盘被建模为图 `G=(V,E)`：

- `V` 是编码后的棋盘点。
- `E` 是棋盘上相邻的印制线段。
- 每条线段保存为二元组 `(start_code, end_code)`。

由于物理线段没有方向，`board.paths` 采用规范形式 `start_code < end_code`。需要有向输入时，`board.directed_paths` 为每条线段同时生成 `(u,v)` 与 `(v,u)`。

每条线段另带 `ROAD` 或 `RAILWAY` 类型，但网络所需的基本端点表示始终是二元组。

- 四国棋盘：288 条无向底层线段（196 条公路、92 条铁路），双向展开后为 576 个二元组。
- 二人棋盘：133 条无向底层线段（98 条公路、35 条铁路），双向展开后为 266 个二元组。

四国主视角中的部分示例：

```text
(0, 1)       自己锋线左端到相邻点，铁路
(0, 120)     自己锋线左端到中央近左点，铁路
(0, 34)      自己锋线左端到左侧敌家锋线右端，铁路
(120, 121)   中央近左到中央近中，铁路
```

二人主视角中的三条战线铁路为：

```text
(0, 34)      自己 (1,1) <-> 敌方 (1,5)
(2, 32)      自己 (1,3) <-> 敌方 (1,3)
(4, 30)      自己 (1,5) <-> 敌方 (1,1)
```

### 5.2 移动动作

训练动作统一表示为有向二元组：

```text
action = (from_code, to_code)
```

`board.action(from_code, to_code)` 只校验二元组表示和编码范围；是否属于下面的静态动作列表由 `board.action_space.contains(...)` 或 `board.action_index(...)` 校验。

这里的动作端点不等同于一条相邻线段。公路移动通常跨一条线段；铁路移动可能跨多条线段，但仍只用起点和终点编码。

### 5.3 静态动作列表

完整规范、数量推导和 Policy Head 映射另见 [四国军棋与二人军棋静态动作编码规范](action_encoding_zh.md)。

`board.actions` 是按 `(from_code, to_code)` 升序排列的静态动作列表。一个动作只有在“至少存在一种棋子和一种局面使它合法”时才会进入列表。生成规则为：

1. 起点是大本营时，删除该起点的全部动作；大本营仍可作为终点。
2. 每条相邻印制线段的两个方向都保留，但仍执行上一条的大本营起点限制。
3. 对铁路图求连通分量。同一铁路连通分量内任意两个不同点的有向组合都保留，因为工兵可在铁路上转弯。
4. 对结果去重，再按起点优先、终点次之排序，得到稳定的动作索引。

因此，行营不是铁路点，它的静态目标集合恰好是周围相邻的印制点；铁路点则保留工兵在无阻挡局面下能够到达的整个铁路连通分量。当前两种标准棋盘的铁路各自只有一个连通分量。

| 棋盘 | 全部非原地有向点对 | 静态动作数 | 永远不可作起点的编码数 | 条件目标最大槽数 |
|---|---:|---:|---:|---:|
| 四国 129 点 | `129 × 128 = 16512` | `5624` | `8` | `76` |
| 二人 60 点 | `60 × 59 = 3540` | `1176` | `4` | `35` |

四国棋盘由此提前删除 `10888` 个永远不可能的有向点对，约占完整非原地点对的 `65.94%`。二人棋盘提前删除 `2364` 个，约占 `66.78%`。

列表同时支持两种训练编码：

- 单头联合动作：`action_index(from_code, to_code)` 把动作映射到 `0..5623`（四国）或 `0..1175`（二人）。
- 两阶段动作：`origin_codes` 提供压缩后的起点编码；选定起点后，`targets_from(start)` 和 `destination_slot(start, end)` 提供条件目标槽。固定宽度目标头只需输出最大 `76` 或 `35` 个槽，多余尾槽静态设为 `-∞`。

示例：

```python
board = FourPlayerBoard()
space = board.action_space

assert space.action_count == 5624
assert space.origin_count == 121       # 129 点减去 8 个大本营
assert space.max_destination_count == 76

action_id = space.action_index(0, 127)
assert space.action_at(action_id) == (0, 127)

target_slot = space.destination_slot(0, 127)
assert space.destination_at(0, target_slot) == 127
```

主视角编码已经把观察者旋转到同一个规范方向，因此每个座位生成的编码动作列表完全相同。

### 5.4 动态合法动作掩码

静态列表只删除“无论何种局面、包括工兵在内都不可能完成”的动作。环境仍必须结合下列信息动态生成合法动作掩码：

- 棋子是否可移动；
- 起点、终点及中间点占位；
- 公路一步限制；
- 非工兵铁路不可直角换线；
- 工兵铁路可转弯；
- 行营、大本营和阵营攻击限制。

地雷、军旗不能移动属于棋子身份限制，不应从某个普通位置的静态动作中删除；行营内已有棋子不可被攻击、己方或盟友占位也都属于当前局面限制。仅凭 `(from_code,to_code)` 不能判断一次长铁路移动是否合法，因为同样的端点可能受中间阻挡影响。底层图和当前占位状态必须保留。

## 6. 策略网络状态输入

策略网络对每个时刻保存一个按 `point_code=0..N-1` 排列的整数棋盘链，再将整盘类别向量通过一个线性层生成 256 维全棋盘嵌入（不创建逐点 256 维 token）。整数码、双明盟友码、512 维“动作 + 动作后棋盘”转移 token 和 1,000 步上下文的完整规范见 [策略状态、棋盘快照与转移 Token 编码规范](state_token_encoding_zh.md)。

整数占位码是类别 ID，不与点编码相加。BoardEncoder 内部仍应把它与下列静态点特征分别 embedding 后融合：

- 点类型：兵站、行营、大本营、中央点；
- 是否位于铁路；
- 点编码/相对位置；
- 游戏模式和信息模式。

四暗模式下，不可见棋子只能标为“未知且属于某相对座位”，不得把真实身份写入棋盘链、动作公开字段或合法动作 mask。真实身份只保留在裁判状态中。

## 7. 不变量

实现和数据管线必须保持：

1. 四国每个视角恰有 `129` 个唯一编码，范围 `0..128`。
2. 二人每个视角恰有 `60` 个唯一编码，范围 `0..59`。
3. `decode(encode(point)) == point`。
4. 改变观察玩家只置换编码，不增删点或路径。
5. 任一视角下路径端点均在合法编码范围内。
6. 物理邻接关系在所有视角下完全相同。
7. 动作 `(a,b)` 的起点和终点有方向；物理线段 `{a,b}` 没有方向。
8. 静态动作列表按 `(from_code,to_code)` 排序，且在所有玩家主视角下完全相同。
9. 静态动作列表不含大本营起点，也不含超出相邻公路或工兵铁路连通范围的点对。

这些不变量由 `tests/test_board.py` 自动验证。
