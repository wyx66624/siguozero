# 70 步无吃子规则与完整断点迁移

v23 配置从训练、评测、人机对局的默认入口取消 2000 步总上限。每名玩家完成一手算一步，
全桌连续 70 步没有吃子自动和棋。战斗中任何棋子被移除即清零：包括进攻获胜、进攻方被吃、
同阶互吃、炸弹同归于尽。普通移动使计数加一，完成第 70 手后判和；夺旗导致团队获胜优先。
终局原因使用 `no_capture_draw`。为兼容已有棋谱，内部 `no_interaction_plies` 与
`GameConfig.no_interaction_draw_plies` 保留存储名称，其含义为无吃子计数和阈值。

配置 `rules.no_capture_draw_plies: 70`、`runtime.max_game_plies: null`、
`model_selection.max_plies: null`。诊断测试仍可显式指定短局上限，结果不能充当完整规则的棋力证据。

四暗、双明完整续训断点从每 5000 万步评测时落盘，改为每 2500 万环境步保存；
评测保持每 5000 万步 100 局。`periodic` 策略的初始化和正常退出也保存完整状态。
二人按 update 的默认保存间隔由 10 改为 5；本地对弈推理快照由每 10 次更新改为每 5 次。
推理快照只含 Policy/Layout，完整 `latest.pt` 另含 Critic、优化器、随机数状态、未结束棋局和历史。

检查点 v7 将计数器嵌入从 0..60 扩展为 0..70。v6 的原 61 行权重和 Adam 动量逐值保留，
新增权重复制第 60 行，新增动量为零；Actor 与 Critic 都迁移。v6 推理快照可直接读取，
v5 及更旧的不同动作编码架构仍不能混用。

对尚未进行过棋力评测的 2000/60 旧运行，先在完整更新边界保存并停止，备份完整断点和
`model_selection/state.json`，然后在原续训命令中增加：

```text
--adopt-current-draw-rules
```

该选项保留已训练参数、优化器、随机数、棋盘、历史、布局状态及累计步数，将未结束棋局切换到新规则。
旧引擎的每次交战都会移除棋子，因此已有无交互计数可按原值继承为无吃子计数。
迁移记录进入断点与选优协议，初始冻结基线保持原文件及 SHA，比较时双方采用同一套新规则。
迁移后立即原子保存完整 v7 断点，后续正常续训不再需要该选项。
已有评测轮次的运行拒绝直接套用此迁移，须建立独立的评测协议，避免混合不同规则下的统计。

旧 `evaluation` 策略的进程没有通用的停止前保存接口；直接发送停止信号会保留上次评测断点，
首次评测前可能完全没有续训状态。不要把推理快照当作完整恢复来源。
