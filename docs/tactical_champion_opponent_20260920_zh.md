**实时冠军＋战术硬规则对手（已实现，默认关闭）**

配置位于 [expand_mappo_training.yaml](E:/agent/siguozero-expand/configs/expand_mappo_training.yaml)：

```yaml
historical_opponents:
  enabled: true
  tactical_champion: false
  start_fraction: 0.3333333333333333
  training_fraction: 0.5
  teammate_fraction: 0.0
```

`tactical_champion: false` 保留原历史对手行为。未来选择这个模式时，在原有历史对手对局份额中使用“实时冠军＋硬规则”，其余仍为自博弈；继承原有启动门槛和对局比例。本次没有更改这些数值：当前门槛仍是 30 亿总步数的 1/3，即 10 亿步，当前预留对手份额为新开局的 50%。它没有增加同时混合两种冻结对手的第三个调度分支，也不自动给历史队友添加规则。

**规则与信息边界**

多条规则同时成立时，按下面的优先级选择第一类有合法动作的规则：

| 优先级 | 条件 | 行为 |
|---|---|---|
| 1 | 存在可吃到已知敌方军旗的合法动作 | 只能从夺旗动作中选择 |
| 2 | 炸弹能合法攻击已知师长、军长或司令 | 只能从这些炸大子动作中选择 |
| 3 | 能合法吃掉或兑掉已知敌方工兵 | 只能从这些消灭工兵动作中选择 |
| 未触发 | 以上均无可行动作 | 使用原冠军策略采样 |

同类存在多个动作时，保留冠军的源位置/目标位置策略，在该类合法动作掩码内采样，并返回实际受限分布的 log-probability；不是任选一个，也不是为这些动作捏造优势。单一强制动作的概率为 1。

“工兵飞到眼前”按可执行规则定义为：其身份已进入该玩家的公开/合法可知观测，而且有合法动作能消灭它。包括工兵互兑或炸弹兑工兵，不包含攻击行营中的不可攻击目标。“明大子”只使用观测中已确认的具体身份；不读取裁判掌握的暗子真值，也不强制猜测尚未确定的军旗位置。

规则函数的输入只有 Actor 的 `PolicyState.current_board` 和 `legal_actions`，明确拒绝 centralized Critic 观测。它不使用此前有敌我过滤问题的 `PublicThreats` 诊断器。

**实时冠军与训练接入**

每轮 rollout 开始时，读取 `model_selection/state.json` 中已提交的 `best_snapshot/best_sha256/best_update`。这是 `best.pt` 的权威来源；读取其不可变快照，避免更新冠军时混到新旧元数据。所有分布式训练进程使用同一广播后的版本，并校验快照哈希、模式、编码版本和规则合同。不会拿 `latest.pt` 冒充冠军；缺少持久化冠军则报错。

一轮 rollout 内参数固定；下一轮看到新冠军才换权重并清空旧推理缓存和旧冠军的待用布局。尚未结束的对局在下一轮跟随新冠军，已经落盘的历史和训练动作不会改写。相同冠军的断点恢复保留排队布局和调度 RNG。

双方敌人席位由这个冻结对手控制，学习者及其队友继续使用原策略。对手动作沿用现有 `learnable=False` 路径，不作为学习者自己的 PPO 动作；但棋局后果继续进入学习者优势和 Critic 的四个视角标签。硬规则对手的胜负不混入普通历史模型的强度抽样 EMA。

关闭状态下不读取冠军，不创建规则 Actor，旧 checkpoint 默认兼容。开启状态会保存不同的抽样合同、冠军身份及规则计数；若已有混合对局，切换策略类别会拒绝静默恢复，避免把旧对手席位解释成另一种行为。当前仍处于自博弈阶段、尚未开始混合采样的旧状态可以加载新模式，但仍受启动门槛控制。

新增观测包括 `historical/tactical_champion_enabled`、`tactical_opponent/champion_update` 以及三种规则和 `model_fallback` 的动作计数。历史对手状态文件同时记录冠军快照身份。

**能帮助克服哪些弱点**

我的判断是：值得作为有针对性的对手，尤其有望缓解“对手也经常放过失误，所以学习者没有稳定付出代价”的问题。这是基于机制和离线覆盖的判断，尚无开启训练后的效果证据。

- 漏防：对方能夺已知旗时必定夺旗，漏防更容易及时产生阵亡/输棋后果，减少失误被对手放过的样本。
- 大子暴露给明炸弹：对方必炸师长及以上，使这种风险更稳定地在轨迹中兑现。
- 工兵暴露：公开确认的工兵进入可被消灭范围后，对方立即吃/兑，减少工兵靠对方忽视威胁而成功的偶然收益。

这类做法与针对弱点设置 exploiter 对手的思路相近。AlphaStar 的 league 包含专门暴露主策略弱点的对手，但其完整系统还包含多样对手和探索机制，不能把论文效果直接当成本项目的效果保证。[AlphaStar 论文](https://www.nature.com/articles/s41586-019-1724-z)、[作者团队对 exploiter 的说明](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)。

它的直接训练作用主要在“防止被对方利用”，不直接保证学习者自己会主动炸大子、扛旗、吃工兵：对手的规则动作没有拿来训练学习者 Actor。学习者仍要探索并获得自己的正向样本。它也不会修复所有 Critic 估值偏差，或保证每一个局部坏动作的 GAE 都为负。

硬规则自身可能被诱导。例如“有明师长一定炸”和“能吃工兵一定吃”忽略了同时存在的防旗任务或其他棋子价值，学习者可能学会诱骗这个专门对手。因此未来衡量效果必须同时看固定公开战术局面上的防守率、相同冻结普通对手下的完整轮换对局，以及本对手下的表现；不能只看对硬规则对手的胜率上涨。

本次没有启用训练，也没有用训练效果指标冒充上述验证。

**为什么 0.000411 不是 −0.36280 的完整目标**

前面的表述需要把“终局奖励的直接贡献”和“完整 λ-return”明确区分。当前采用 GAE / λ-return；它在中间回合仍使用 Critic 的估值，而不是只把最后一笔奖励乘以 `λ^N`。[GAE 原论文，第 3 节](https://arxiv.org/html/1506.02438v6)。

在 γ=1 的一个个人回合边界，可写成：

`G_t = R_t + (1−λ) V_old(s_next) + λ G_next`

这里 `R_t` 是这个个人回合间隔内积累的个人奖励，`s_next` 也包括阵亡玩家应当再次轮到行动时的虚拟估值点。它不是其他棋局优势的平均。

对之前真实样本 update 1270、第 323 步的分解：

| 组成 | 贡献 |
|---|---:|
| 下一步本人被夺旗 | −0.200000 |
| 152 个虚拟个人回合后的胜利直接项，`0.95^152 × 1` | +0.000411 |
| 这些边界上中间 Critic 估值的加权和 | −0.163207 |
| **完整 λ-return / Critic target** | **−0.362796** |

再减去行动前估值：

`A = −0.362795929 − (−0.462890625) = +0.100094696`

因此衰减没有失效：最后一笔 +1 的直接项确实只剩 0.000411；但完整目标还包含另外两项。即使把终局直接项完全删掉，目标仍约 −0.363207，高于原先 −0.462891 的基线，优势仍会为正。

更一般地，若这 152 个中间 V 都准确预测为 +1，则它们的权重和为 `1−0.95^152`；加上终局直接项后，总和仍是 +1。这说明 **λ 控制的是 TD 误差与 bootstrap 的混合，不能代替对奖励目标的时间折扣**。在 γ=1 下，仅补齐阵亡后的 λ 边界，并没有把目标改成“队友很晚赢对我几乎没有价值”。

如果目标确实是让阵亡后很遥远的队友胜利对本人总价值趋近零，就属于另一个目标/折扣设计问题，不能只看 `λ^152` 就认为已实现。本次未修改这一机制，γ=1、λ=0.95 保持不变。
