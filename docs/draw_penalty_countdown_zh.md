# 和棋负奖励与六维步骤输入

2026-09-11，配置 revision 24，checkpoint 格式 8。

终局**训练奖励**统一为：胜 `+1`，负 `-1`，和棋 `-0.15`。非终局奖励仍为 `0`。
连续 70 个全局行棋步骤没有任何棋子被移除则和棋；吃子、兑子、炸弹互毁等会重置计数。
没有总对局步数上限。采样批次或历史窗口结束不等于和棋，也不产生惩罚。
诊断模式显式设置的总步数上限如果产生和棋，也使用相同终局训练奖励。

规则引擎的 `game.rewards()` 保留胜负结果 `+1/0/-1`；训练入口通过
`terminal_utility()` 映射奖励。这样统计仍区分胜、和、负，评测中的和棋仍计半分，
不会因为奖励为负就被误记成败局。PPO、二人 GRPO 终局续局和布阵回报均使用新奖励。

每条已执行动作的模型输入为：

```text
[起点 x, 起点 y, 终点 x, 终点 y, 相对行棋玩家, 距离 70 步和棋的剩余步数]
剩余步数 = max(0, 70 - 该步走完后的连续无吃子步数)
```

第六项为未归一化的 `0..70` 数值：无吃子第 1 步是 69，第 69 步是 1，
第 70 步是 0；发生吃子后恢复为 70。这是所有玩家都能知道的公开信息，不读取隐藏身份，
也不提前给未执行的候选动作注入战果。没有历史动作的初始 token 和 padding 仍严格屏蔽为零。
四暗、双明使用 `Linear(6,128)`；二人使用 `Linear(6,256)`。

历史文件仍保存起点、终点、行棋玩家三元组和已有的无吃子计数，不重复存储倒计时。
普通历史、数组历史、CPU 环境打包、固定 KV、CUDA Graph、普通和变长 learner
都从同一计数构建第六项。旧历史可以原样恢复。

## PPO 回报的必要修正

和棋双方都为 `-0.15`，训练奖励不再是零和的。不能直接在旧 GAE 中给所有回报乘
“同队 +1、异队 -1”，否则对手走完和棋会被错误翻成 `+0.15`。

独立 Critic 的同一个编码器现在输出两个标量：队伍胜负价值 `Z` 和共同和棋惩罚价值 `C`，
总价值为 `V=Z+C`。训练终局奖励分成 `rZ` 与 `rC`：胜负时为 `(+1/-1,0)`，
和棋时为 `(0,-0.15)`。令 `d=0` 表示终局、其他为 1，`sigma` 为下一行动者队伍符号：

```text
deltaZ = rZ + gamma * d * sigma * Z_next - Z
deltaC = rC + gamma * d * C_next - C
AZ = deltaZ + gamma * lambda * d * sigma * AZ_next
AC = deltaC + gamma * lambda * d * AC_next
策略优势 A = AZ + AC
价值目标 = Z + AZ 与 C + AC
```

两个价值分量分别使用 clipped value loss；不额外执行 Transformer 前向。
终局同时截断两个 GAE 分量；采样边界同时 bootstrap 两个分量。
`lambda=1, gamma=1` 的整局和棋对所有步骤回传 `-0.15`；实际 `lambda=0.95`
的 GAE 目标会混合冻结价值估计，不能要求每个中间样本都恰好等于终局奖励。

## 完整断点迁移

格式 6/7 的动作投影保留前五列，第六列补零；Adam 的对应新列也补零。
格式 6 的计数 embedding 仍按 revision 23 扩展。旧 Critic 的全部权重和 Adam 状态保留，
新增和棋价值头从零开始，其 Adam 状态由第一次梯度更新创建。冻结历史模型可直接推理，
不会重写 baseline 或 `best.pt`，首次加载的旧模型输出保持不变。

继续旧奖励训练断点时需显式使用 `--adopt-draw-penalty`，避免普通恢复无意改变目标。
此操作保留 update、全部环境步数、未结束棋盘、历史、RNG、学习率缩放、布阵状态和优化器。
布局缓冲中已完成和棋的旧零奖励重映射为 `-0.15`。迁移轮次写入
`trainer_state.draw_objective_migration`，恢复后保存格式 8 的完整 `latest.pt`。
已经暂停的其他模式不会被自动启动。

`critic/draw_value_mse`、`critic/draw_target_mean`、`critic/rollout_draw_target_mean` 等。
迁移后重新建立完整 update 的吞吐基线，继续检查环境步数是否逐步进入 PPO、
优化器步骤/epoch、KL、熵、有限损失、和棋率及保存记录。
负奖励改变了价值目标，迁移前后的损失数值不能直接解释为棋力变化。
