# 双人军棋对齐 expand 四暗 ACPO + MAPPO

配套可视化见[双人专用控制台](two_player_console_zh.md)，默认端口 8767，包含训练监控、CPU 对弈与明棋复盘。

双人入口与 `scripts/start_two_player_main.sh` 现在默认使用
`configs/expand_mappo_training.yaml`。模型、优化器、优势计算、裁剪和 KL/LR 控制复用四暗实现，
模式差异由配置覆盖项明确表达。四暗的有效参数保持不变。

## 编码与模型

每个棋盘位置仍用 25 个库存候选槽及一个相对归属特征。Actor 只能看到自己的信息和公共推理出的候选，
Critic 使用单独保存的全知历史，每个实体棋子占据持久的单独槽位。

| 项目 | 双人 | 四暗 |
| --- | --- | --- |
| 棋盘位置 | 60 | 129 |
| 棋盘投影输入 | `60 × 26 + 3 = 1563` | `129 × 26 + 3 = 3357` |
| 棋盘投影输出 | 384 | 384 |
| 行动投影 | 14 → 128 | 14 → 128 |
| 融合 | concat 512 → SwiGLU 512 | 相同 |
| Actor / Critic | 各 16 层，8 头，FFN 1024 | 相同 |
| 动作头 | 60 个起点，60 个条件落点 | 129 个起点，129 个条件落点 |

行动输入保留四个坐标、相对行动者、无吃子倒计时、存活位及剩余跳过次数；双人不存在的席位填零。
Actor 按起点再按条件落点采样。普通前向、数组/packed 学习、固定 KV 缓存和检查点均识别 60 点容量。
双人的每个环境动作产生一个 Actor 决策和两个 Critic 视角标签；冻结历史对手的动作不训练 Actor。

## 奖励与历史对手

双人只使用终局奖励：胜 `+1`、负 `-1`、和 `-0.15`。吃旗、进入已知非军旗大本营、炸大子、
明知打不过仍送子的额外奖励或惩罚全部为零，包括吃旗直接结束比赛的那一步。
四暗的这些奖励保持原配置，炸司令/军长/师长基准仍为 `0.03 / 0.01 / 0.003`，
明知打不过仍送子的惩罚基准仍为 `0.01`，原有随训练进度衰减的规则不变。

默认总预算仍为 30 亿环境步。每跨过 2500 万环境步边界，在该次完整更新结束后保存模型版本。
正常停止仍额外保存恢复断点。完整优化器/棋局存档保留数量沿用四暗的 3 份；已存历史模型版本继续保留。

5 亿环境步之前只进行当前模型自对弈；达到 5 亿后，新棋局按 80% 当前自对弈、20% 历史对手配置分配。
门槛单独用整数 `start_environment_plies: 500000000` 固定，不因总预算调整而提前。
历史模型从 2500 万步版本起纳入候选，沿用四暗的失利率 EMA/softmax 采样：
新版本初始失利率 `0.5`、EMA 系数 `0.01`、温度 `0.1`，和棋不更新失利率。
没有历史队友，也没有当前战术规则模型作为额外对手。两名学习方席位均衡轮换，冻结对手只推理，
它的模型、分配状态及未完成棋局可恢复。

评测沿用每 5000 万步挑战冠军、500 局；双人采用完整的两局换边组，不带历史队友。
评测是独立冻结对局，不计入训练的 5 亿步历史对手启用门槛。

## ACPO、MAPPO 与学习率

使用与四暗相同的个人决策时刻 GAE，`gamma=1`、`lambda=0.95`。
每轮采集 98,304 环境动作，Actor 优化器批量 1,024、微批 32；Actor 最多 3 个 epoch，Critic 完整 3 个。
Critic 的批量和标签数按实际视角数扩展，双人为两份而非四份。

ACPO 复用当前实现的优势自适应上界：

```text
A = 全局归一化后的带符号优势
ratio 下界 = 0.80
ratio 上界 = 1.20 + 0.05 * Phi(A)
```

没有进度收窄日程、额外 epsilon 硬限幅或大优势免裁剪。动作熵沿用
`0.005 H(joint) + 0.005 H(source)`，等价于选子系数 `0.01`、条件落点系数 `0.005`；
布阵熵系数 `0.01`。

Actor/Critic 初始学习率均为 `1e-5`，范围 `1e-6..1e-4`，Critic 按与 Actor 的初始学习率比例同步调整。
保持首遍 Actor 样本覆盖完整；使用固定最多 8,192 个探针样本，在 epoch 末及后续 epoch 每 16 次优化器更新检查平均 KL。

- 第一或第二个 epoch 内（包括第二个末尾）遇到 `KL > 0.10`：停止后续 Actor 更新，下轮学习率乘 `0.95`。
- 完成全部三个 epoch 且最终 `KL < 0.05`：下轮学习率乘 `1.05`。
- 其余情况保持学习率；KL 超过 `0.10` 仍执行相同的 Actor 早停规则。

这些数值来自当前四暗配置及共用控制器，没有为双人另建一套近似规则。

## 启动与兼容性

```bash
bash scripts/start_two_player_main.sh
# 等价的显式入口
python -m junqi.training.train_two_player \
  --config configs/expand_mappo_training.yaml --model-scale main --device cuda
```

新模型保存到 `runs_expand_mappo/two_player/with_dead_rules`，与四暗目录隔离。
旧 GRPO 的结构与优化器状态不能直接续入新模型；旧目录不被迁移或覆盖。
显式传入 `--config configs/bootstrap.yaml` 仍可加载旧 GRPO 配置。

验证覆盖双人真实 CPU 采样/学习、60 点前向与 packed/KV 数值一致性、终局奖励、历史对手轮换和学习掩码、
未完成棋局及优化器恢复、推理加载、保存边界和四暗配置不变。修改本身不启动双人正式训练。

本次完整 CPU 回归为 `987 passed, 23 skipped, 646 subtests passed`；最后的双人、MAPPO、历史对手及
评测兼容性回归为 `87 passed, 2 skipped, 60 subtests passed`，包含两个环境进程的双人历史对手采样。
默认命令行入口的微型模型完成一次 8 环境步短训练，生成 8 个 Actor 决策、16 个 Critic 标签并保存断点。
该断点完成两局换边评测，结果仅用于验证流程。主模型结构另行核对为 `1563 → 384`、`14 → 128`、
16 层 Actor/Critic；未启动双人完整规模的 GPU 训练，也未作棋力或吞吐结论。
