# 开局趋同与探索诊断（2026-09-12）

后续实现记录：本文取证后，行棋策略已经接入[自适应探索熵](adaptive_entropy_zh.md)。下文关于固定系数和未接入开关的内容描述取证时版本；新代码的长期棋力收益仍需后续训练与评测确认。

结论：已在 CPU 上复现第 935 轮模型的开局趋同。模型对一个相对坐标走法、尤其是同一个己方行营，存在很强的偏好；网页低温度会进一步放大这个偏好。当前证据支持“开局探索范围明显收窄”，尚不足以判断这个开局一定不好，或模型整体棋力已经回退。

## 取证范围

- 正式运行目录：`runs_local_4090/four_dark/with_dead_rules`，四暗棋、启用明死规则。
- 检查网页实际 CPU 会话，加载的是第 935 轮快照；正式训练保存到第 939 轮、92,307,456 环境步（30 亿目标的 3.077%），取证时状态为停止。
- 比较冻结的第 925、930、935 轮快照，三个文件 SHA-256 不同。
- 用第 935 轮模型生成 32 个不同的随机布阵，每局运行前 12 个全局行动，共 384 次行动。四个座位都由同一模型在温度 0.7 下采样。
- 固定上述对局中前四步的 128 个观测，比较三个模型在完全相同观测上的完整合法动作概率。
- 全程 CPU、2 个计算线程，`CUDA_VISIBLE_DEVICES` 为空，`cuda_initialized=false`。没有创建或修改用户网页中的棋局。

这些是开局分布诊断，不是完整对局胜率评测。不同座位、同局中的观测有关联，本文不把 128 个观测当作独立胜率样本，也不由此推算棋力。

## 实测结果

### 动作和落点同时集中

在 32 局、四方各第一次行动的 128 次采样中：

| 项目 | 结果 |
| --- | ---: |
| 进入己方行营 | 125 / 128（97.66%） |
| 进入同一个相对行营，编号 18 | 117 / 128（91.41%） |
| 同一个相对坐标动作 `22 → 18` | 89 / 128（69.53%） |
| 32 局各自的第一个动作是 `22 → 18` | 21 / 32（65.63%） |
| 32 局首步的不同动作数 | 7 |
| 32 局前四步的不同动作序列数 | 20 |

`22 → 18` 对应己方第 5 排第 3 列移入第 4 排第 4 列行营。策略输入按行动者视角旋转，四方共享同一组权重，因此同一个相对招数在网页上会呈现为不同方向上的旋转动作。这与截图中几方先移动后排中间棋子的现象相符；截图本身没有完整棋谱，不能单凭截图确认每个历史动作。

这个偏好也不是只针对一种棋子：在最高概率动作是 `22 → 18` 的 89 个观测中，起点出现了全部 10 类可移动棋子，包括炸弹、工兵和各级军官。该证据提示存在很强的位置偏好；它还不是对“模型完全忽略棋子身份”的证明。

### 提高网页温度只能部分缓解

以下数值都是在同一批 128 个观测上逐个计算后取平均；温度调整只作用于行棋，保持观测和布阵不变。

| 行棋温度 | 最高概率动作的平均概率 | 进入己方行营的平均概率 | 开局平均动作熵（nat） | 熵 / log(合法动作数) |
| --- | ---: | ---: | ---: | ---: |
| 0.3 | 85.21% | 99.93% | 0.340 | 8.85% |
| 0.7，网页默认 | 78.82% | 98.88% | 0.654 | 17.03% |
| 1.0，训练采样温度 | 75.30% | 98.10% | 0.868 | 22.62% |

每个观测平均有 47.28 个合法动作。在温度 1.0 下，仍有 88/128 个观测把超过 95% 的概率分配给单个动作。网页温度并非全部原因：训练使用的概率分布本身已经非常集中。

注意开局合法动作本身存在结构偏向：若对所有合法动作均匀采样，平均进营概率已经是 64.77%；若先均匀选择可动棋子、再均匀选择该棋子的合法落点，则达到 87.37%。当前动作头采用“起点、条件落点”两阶段分解，但实际概率是学习出来的，并非均匀分层采样。这个对照说明，不能把所有进营行为都解释成学习失败；与此同时，98.10% 和单个动作超过 95% 的集中程度仍值得检查。

### 相邻快照确实保留了相似开局

在温度 0.7 下，与第 935 轮比较：

| 冻结快照 | 最高概率动作一致的观测比例 | 平均总变差距离 |
| --- | ---: | ---: |
| 第 930 轮 | 96.09% | 0.01334 |
| 第 925 轮 | 91.41% | 0.02413 |

总变差距离为 `0.5 × Σ|p(a)-q(a)|`。模型文件不同、输出概率也发生变化，只是短时间内高概率开局保持相似。不能由“又走同一步”推断没有加载新模型或参数完全没有更新。

## 已检查的实现因素

1. **网页新局种子并未固定。** `src/junqi/web/server.py` 的新局接口默认使用 `secrets.randbelow(2**31)`，网页不显式传固定 seed。CPU 会话初始化时设置 Python/Torch 随机种子。恢复现有会话仍是原来的棋局，原棋局使用的快照也不会随训练更新自动更换。
2. **CPU 动作采样使用 multinomial。** `src/junqi/training/models.py::sample_action_groups` 分别随机采样起点与落点。固定一个观测，在三个温度下各抽样 4096 次，分别出现 16、45、50 个不同动作；经验分布与理论分布的总变差为 0.0075、0.0313、0.0282。没有发现 argmax 冒充随机采样的情况。
3. **缓存没有在本次观测上造成概率重复。** 对 128 个观测清除推理缓存、调用完整历史编码重算，温度 0.7 下各动作概率与原结果的最大差值为 0。此检查限定于这批短历史 CPU 观测，不覆盖 GPU 长历史的所有路径。
4. **熵自适应开关尚未接入实际训练。** YAML 的 `adaptive_to_target_entropy: true` 只出现在配置中；`TrainingSettings` 读取的是 `entropy_coefficient.initial`，训练损失使用这个固定系数。第 939 轮保存配置中为 0.01，未发现按目标熵调节的运行逻辑。
5. **全局平均熵会掩盖开局集中。** 最近 100 轮行棋熵约为 1.985–2.115，而本次开局观测在训练温度下只有 0.868。两者采样范围不同，不矛盾。应把开局和后续阶段分开统计。

当前 PPO 行棋损失包含裁剪策略目标与熵奖励，没有把行棋策略固定到最初模型的 reference-KL 损失项。日志中的 `approx_kl_old` 对应当前批次行为策略与更新策略的差异，不能据此认定旧检查点锁住了开局。

PPO 原论文第 5 节明确用熵奖励支持探索，但这并不保证每类局面都保有足够多样性。分阶段统计、设定目标与验证收益，仍是本项目需要做的工程工作。[Schulman et al., 2017](https://arxiv.org/pdf/1707.06347)

## 另外发现的布阵学习滞后

直接读取第 939 轮保存的训练状态：

- 布阵结果队列有 808,780 条；队首待学习的 64 条全部来自第 95 轮，奖励全部为 -0.15。
- 最近 100 轮中，66 轮的布阵奖励标准差和布阵策略损失为零；相同奖励经标准化后不能提供区分好坏布阵的优势信号，剩余更新来自熵与信赖域项。
- 队尾最近 1024 条已经包含 440 胜、440 负、144 和的奖励记录，说明新对局有胜负反馈，只是旧 FIFO 消费速度跟不上。
- 当时保存配置每轮消费 64 条，而最近 100 轮平均完成 228.78 局，四方产生约 915 条布阵结果。队列持续增长是可由代码和保存状态共同确认的问题。

这影响布阵对真实胜负反馈的适应，不能直接当作行棋总进营的唯一原因。

**并行工作状态说明：** 分析期间，工作区已出现新的有界布阵缓冲、最大行为版本年龄和分微批学习实现，配置为容量 8192、最大年龄 8、每轮最多 2048 条、微批 32。本节数字来自第 939 轮保存的旧状态；本次没有验证新实现恢复训练后的效果，不把旧队列问题描述为新实现必然仍存在。

## 下一步优先级

1. 按实际全局 ply 分段记录开局动作熵、归一化熵、最大动作概率、起点/落点集中度及进营比例。优先复用 PPO 已计算的概率统计，以少量固定 CPU 观测补充，不额外创建常驻 GPU 模型或全量搬运 logits。
2. 实现并验证配置中声明的目标熵调节；若要对开局施加额外探索，应先做冻结起点、多随机种子的对照实验。目标是发现更好的可行策略，不是让所有动作等概率。
3. 验证新布阵队列的最大样本年龄、实际消费量和有胜负优势的批次比例，并同时测量更新耗时与内存，确认旧样本滞后得到解决。
4. 固定同一批布阵和座位轮换，对比当前开局与替代开局的完整对局结果；替代开局需要合法且明确标记为受控干预。评测使用相同对手、队友和完整规则，不能用升温后“走法变多”替代棋力评测。
5. 历史对手与历史队友混合按现有设置在 15 亿步后开始；这次约 9231 万步的模型尚未使用该混合。它属于对手/队友多样性，与单一观测上的动作探索是两个层面，不能相互替代。
