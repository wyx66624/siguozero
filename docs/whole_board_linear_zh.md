# 整张棋盘单层编码

整盘修改记录：revision 20，2026-09-10。四暗、双明和二人行棋模型均使用该棋盘编码。
revision 21 还将动作输入改为[五维坐标单层投影](action_linear_zh.md)。本文的
参数变化与计时保留 revision 20 测量口径；当前总参数见[四国 PPO](four_player_ppo_zh.md)。

**revision 22 更新**：四暗、双明的投影输出改为 128 维（开启死规则时 2,305,280 参数），
与 128 维动作向量拼成 256 维 token；二人保持原宽度。下文 256 维公式保留为历史说明，
当前实测见[128＋128 并行训练核算](compact128_parallel_training_eta_zh.md)。

revision 20 的 30 亿步时间核算见[整盘单层编码后的训练时间](whole_board_ppo_eta_zh.md)，
包含双明补测、完整评测计时、保存开销和多卡条件情景。

按原有码表和玩家视角生成完整棋盘整数链，然后将整盘类别特征组成一个固定向量，
整个向量只经过一个可训练线性层，输出一个 256 维棋盘向量。

```text
129 点类别码（四国）或 60 点类别码（二人）
  → 固定点位顺序的整盘 one-hot + 模式 + 可选阵亡位
  → 单个 Linear → 256 维棋盘向量
  → 与 256 维动作向量 concat → 512 维历史 token
  → 原有时序 Transformer
```

类别展开没有可训练参数，不把棋子类别 ID 当作军阶数值，也不创建每点 256 维向量。
实现直接生成二维 `[棋盘数量, 整盘特征维数]` 张量，删除了逐点 Embedding、
棋盘图注意力、棋盘 Transformer、池化 token 和逐点输出。

四国棋盘的点位和可见信息规则保持原定义。类别维度为 `129 × 139 = 17,931`；
再加 3 维模式 one-hot。死规则开启时拼入 75 维规范阵亡位，总输入 18,009 维；
关闭时删除对应的输入列，总输入 17,934 维。两者都只有一个线性投影，输出 256 维。
二人棋盘的后 69 个点槽为零；实际空点激活空点类别，与填充位置不同。

动作头也作相应调整：从时序上下文直接预测起点位置 logits，再根据上下文与起点
one-hot 预测终点 logits，两个阶段保留裁判提供的合法动作 mask 和概率采样。
不再通过最新棋盘的逐点特征计算动作分数。Layout 的 25 子布阵网络不属于行棋棋盘编码器。

Policy 和 Critic 各有独立的整盘投影，双方均端到端学习。采样用的整盘向量缓存、
时序 KV Cache、同一次学习的历史前缀合并继续使用；完整命中的缓存状态无需再次编码棋盘。

## 参数与计算量

main 开启死规则时：

| 模块 | 修改前 | 修改后 |
|---|---:|---:|
| 单模型棋盘编码器 | 8,633,608 | 4,610,560 |
| Policy | 144,157,704 | 140,036,866 |
| Critic | 143,698,441 | 139,675,393 |
| Layout | 17,292,288 | 17,292,288 |
| 可训练参数合计 | 305,148,433 | 297,004,547 |

计数由 revision 20 模型在 PyTorch meta 设备上复算，见
[各档位参数](benchmarks/whole_board_parameters_20260910.json)。

一次棋盘前向的主要矩阵 FLOPs（一次乘加计 2）：

- 修改前的 8 层棋盘 Transformer：约 2,319,482,880 FLOPs。
- 当前整盘投影：`2 × 18,009 × 256 = 9,220,608` FLOPs。

这个模块的主要前向矩阵计算约减为原来的 **1/252**。这不是整段训练的加速比：
时序网络、采样环境、数据整理、优化器、检查点和评测仍有开销；展开整盘向量也有搬运成本。
先前关于 5330 张棋盘产生 692,900 个点 token 的剖析属于旧架构。
新结构中的 5330 张棋盘产生 5330 个整盘向量，没有该点 token 序列。

## 验证

219 项回归测试全部通过，包括 GPU 缓存一致性、历史前缀训练及梯度、
两阶段采样概率和合法性、PPO 双模型更新、检查点恢复和分布式选拔协议。
新增测试还检查三种模式的单层整盘输入、点位类别无碰撞、填充、阵亡特征开关和旧格式拒绝。

RTX 4090 的 main 容量测试：microbatch=8，每条独立历史 1001 token，FP32 参数、
BF16 autocast、时序激活重算，Policy/Critic/Layout 的 Adam 状态均初始化，冻结 Layout 常驻。
Policy 和 Critic 分别完成两次梯度与优化器更新；峰值分配显存 **5.08 GiB**，
第二次 Policy/Value 更新分别约 **0.689 / 0.671 秒**。
这是合成独立历史的学习阶段测试，不代表实际棋力或完整采样阶段的峰值显存。
详见[容量测试原始数据](benchmarks/whole_board_ppo_4090_20260910.json)。

真实四暗短测使用 20 局并行、每轮 5120 个环境动作，共两轮 10,240 步。
采样与 PPO 学习合计 **152.6 秒**（不含保存），峰值分配显存 **15.83 GiB**；
单次独立检查点保存约 11.2 秒。相同配置旧架构的对应短测为 306.4 秒，
本次约快 **2 倍**。两次都是随机初始化且实际轨迹不同，这不是固定训练数据的严格 A/B，
也不能据此承诺整个 30 亿步训练的加速比或棋力。
本次尚无非零终局优势，双模型非零目标的更新能力由上面的容量测试和 PPO 单元测试覆盖。
详见[真实采样与学习数据](benchmarks/whole_board_real_ppo_4090_20260910.json)。

## 检查点

整盘结构在 revision 20 使用格式 5。当前 revision 21 使用 **格式 6**，同时保存
`board_encoder_type=whole_board_one_hot_linear` 和 `action_encoder_type=coordinates_player_linear`。
旧格式 4/5 的棋盘或动作编码器与当前权重不兼容；训练恢复、初始化和推理入口明确拒绝直接加载。
切换架构应选择新的 run-dir，旧训练目录和权重文件保留。
`--init-from` 的 GRPO→PPO 初始化仅适用于同为当前格式 6 的网络。

训练仍以总环境交互预算 30 亿步计数。四暗、双明仍从 0 步建立基准，
每 5000 万环境步以 100 局选拔；编码器前向和重复学习不增加环境步。
