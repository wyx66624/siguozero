# expand：25 槽库存编码、384 + 128 维输入与集中式单值 Critic

本分支新增配置 `configs/expand_mappo_training.yaml`，用于四暗与双明的扩展模型。
四国模式现使用棋盘 384 维、动作 128 维的新输入，保留 expand 原有的 512 维主干、
16 层 Actor/Critic、布阵网络、奖励和训练日程。所有配置的棋盘与 Actor 历史现统一使用多热库存编码；
`local_4090_training.yaml` 与二人模式保留各自的模型宽度、深度和训练算法。
实现阶段在独立的 `siguozero-expand` 工作目录完成 CPU 回归；后续 CUDA 验证、训练配置与监控服务
见 [expand 训练启动记录](expand_training_launch_20260918_zh.md)。

## 模型结构

| 部分 | 原四国 main 配置 | expand 配置 |
| --- | --- | --- |
| action 单层投影 | 128 维 | 128 维 |
| state 整盘单层投影 | 128 维 | 384 维 |
| action/state concat | 256 维 | 512 维 |
| concat 后融合 | 直接进入时序主干 | 一层 SwiGLU，输入/输出均为 512 维 |
| Transformer 宽度 | 256 | 512 |
| 注意力头数 | 8 | 8 |
| 每个注意力头维度 | 32 | 64 |
| Actor 层数 | 32 | 16 |
| Critic 层数 | 32 | 16 |
| Critic 输出 | 胜负与和棋两个分量 | `Linear(512, 1)`，一个 V 值 |
| Transformer 内部 FFN 隐藏维度 | 1024 | 1024 |

“32 改为 64”按**每头维度**实现，实际头数保留 8。配置中的 `attention_heads` 表示头数。

融合层执行：

```text
action ── Linear → 128 ─┐
                       ├─ concat 512 → SwiGLU 512 → 加位置/模式/当前行动方 → Transformer
state  ── Linear → 384 ─┘
```

SwiGLU 将输入分别投影成 512 维 gate 和 512 维 value，计算 `SiLU(gate) * value`，
再投影到 512 维。普通前向、数组批处理、增量 KV 推理和学习图共用这一融合规则。

Actor 与 Critic 使用相同的输入投影、融合模块、时序块结构，但参数、优化器和缓存独立。
Actor 与 Critic 均为 16 层。Critic 初始化时复制 Actor 的对应投影与全部 16 层；随后独立学习。
Actor 的动作输出头仍为 256 维隐藏层。布阵网络与布阵奖励沿用 expand 原有设置。

## 每个位置的 26 个输入

Actor 的前 25 维对**已确认棋子使用独热槽，对身份未定棋子使用多热候选槽**，不表示概率。
Critic 的前 25 维是每枚真实棋子各自占用的独热槽。第 26 维均为单个归属编号。

| 槽位（从 1 开始） | 子力 |
| --- | --- |
| 1 | 军旗 |
| 2–4 | 三枚地雷 |
| 5–6 | 两枚炸弹 |
| 7–9 | 三名工兵 |
| 10–12 | 三名排长 |
| 13–15 | 三名连长 |
| 16–17 | 两名营长 |
| 18–19 | 两名团长 |
| 20–21 | 两名旅长 |
| 22–23 | 两名师长 |
| 24 | 军长 |
| 25 | 司令 |
| 26 | 自己/右家/对家/左家分别为 1/2/3/4；无子为 0 |

空位置的全部 26 维都是 0。Actor 的己方三个工兵分别使用 `100`、`010`、`001`，其他棋种槽
均为零；己方所有棋种及双明可见队友同理，编号与 Critic 一致。编号跟随棋子移动，阵亡后
不重排存活棋子的编号，也不把已使用编号分给后来确认的另一枚棋子。

对于暗棋其他玩家，首次确认一枚工兵时分配 `100`，下一枚分配 `010`，再下一枚分配 `001`。
分配只使用该观察者合法可知的身份和确认顺序，同一步同时确认时按棋主的棋盘位置排序；
不会取用对手的裁判真实编号。只有候选缩小到唯一棋种后才分配独热槽。

身份未定、仍可能是工兵的位置初始保留工兵三槽 `111`。确认一枚为 `100` 后，该观察者对
同一玩家其他位置的这个槽全部清零，未知位置的工兵候选变为 `011`；再确认 `010` 后变为
`001`，三枚都确定后为 `000`。其他棋种同理；不同玩家及不同观察者的槽位独立维护。

已确认棋子阵亡时，其编号继续排除，不会再次扣除另一枚棋子的名额。例如 `100` 已被定位时，
其他位置是 `011`，该棋子阵亡后仍是 `011`。只确定死亡数量、没有对应已分配编号的损失，
从尚未分配的槽中按高位依次扣除：无已确认编号时仍是 `111 → 110 → 100 → 000`；
已有 `100` 在场且另有一名匿名工兵确认阵亡时，其他位置只剩 `010`。存活的已确认棋子
始终保留原编号。多热候选的每个 `1` 表示尚未被已确认棋子或确定损失占用的名额。

Critic 则在每方各自的 25 槽中给每枚子分配唯一编号：三个工兵分别使用第 7、8、9 槽，
对应工兵三维中的 `100`、`010`、`001`，地雷、炸弹及其他重复子力同理。
编号在初始局面按各自座位的棋盘位置确定，之后跟随棋子移动；阵亡后空出该槽，
其余同类棋子不重新编号。不同视角、clone、环境进程和训练池保存/恢复都保留相同编号。
Actor 仅对己方与合法可见队友使用这些一致的编号；隐藏对手的确认编号独立分配。输入总维数不变。

整盘输入为 `129 × 26 = 3354` 维，按原架构继续拼接 3 维模式、75 维确定阵亡槽及 4 维剩余跳过次数，
总计 **3436 → Linear → 384**。原有阵亡槽保留原来的次序，布阵解码器的投子次序也不变。
行动投影改为 **10 → Linear → 128**：起点 x/y、终点 x/y、上一手行动者、
无吃子和棋剩余步数，以及按观察者相对座位排序的四个玩家存活位（每位 0/1）。
无吃子倒计时和存活状态只进入这一次行动投影，不再单独添加 embedding。
没有前一手的初始 token 仍编码倒计时和存活状态，只将起终点和上一手行动者字段置零。
当前轮到谁走仍通过 `current_player_embedding` 加到融合后的 token；位置和模式嵌入也保留。
移除独立的亮旗状态 embedding；规则层仍保留亮旗事件及其产生的合法可见棋子身份与候选约束。

数值历史不保存稠密的 3354 个浮点数：每个位置的 25 位候选压成两个正 `int16`，
模型前向时再展开。四国每个视角每个历史 token 为 476 个 `int16`（952 字节），
旧的 218 个 `int16` 历史格式会被明确拒绝。原始棋盘代码仅用于位置归属、接口和调试，
棋盘投影不再包含 139 类独热分支。每条 Actor 历史必须包含 25 槽候选信息。

## 持续推断与信息边界

每位观察者独立维护每枚在场棋子和已移除棋子的候选集合；工兵飞行、交战后留下的非单一候选、
初始布阵限制都跟随棋子，而不是重新按当前位置猜测出生限制。

- 初始第一排不能放任何炸弹；地雷限后两排，军旗限大本营。
- 移动排除军旗和地雷，只有工兵可完成的铁路路径证明工兵身份。
- 交战保留所有与公开结果、合法可知身份及亮旗事件一致的类型；不会把未知同归于尽默认成对掉或炸掉。
- 司令阵亡亮旗后，其他本方在场子排除司令，另一个大本营排除军旗。
- 每方 25 个变量与初始 25 槽做可行匹配，去掉不能出现在任何可行库存分配中的候选。
- 对各类型检查最多还可能有多少枚在场，从而得到确定阵亡数量下界，即使不能指出具体哪次暗交换损失了它。

阵亡但身份未知的变量会继续保留，后续得到的新信息仍能收紧库存。数据随 clone、环境进程传输、
训练池存档与恢复保存，超过 Transformer 的历史窗口也不会遗失。复原中局时没有证据的缺子保持匿名未知，
不会读取裁判隐藏身份补齐 Actor 的计数。公开身份、己方身份和双明合法队友身份遵循原有可见性规则。

这比原先“未知棋子一个代码”提供更多确定信息，但不是全知信息或完整的联合后验。
每次同归于尽现在还保存观察者当时认可的双方身份组合，按步数关联两名阵亡子的持久记录。
每次新证据进入后，库存匹配与这些历史组合反复收紧，直到候选不再变化。例如早先的“连长或炸弹”
交换，在后来另两枚炸弹的死亡分别得到确认后，会回溯成连长对掉，更新确定阵亡位及当前存活子候选。
双方都未知时，也可以先确定“同军阶对掉”，继续保留“连长对连长或排长对排长”等关系；
日后某一方的库存进一步收紧时，另一方的历史阵亡身份会一起更新。

反过来，后来证实某军阶的名额已全部由其他棋子占用，也能确定旧交换消耗了炸弹。例如双方司令
已经阵亡，己方军长与敌方未知子同归于尽，先保留敌子为“军长或炸弹”；后来敌方另一枚可移动子
吃掉己方师长并存活，或己方师长攻击已移动过的敌子失败，就能确定它是敌方唯一军长。
旧交换中的敌子因此只能是炸弹，确定炸弹阵亡数加一，当前炸弹候选槽由 `11` 收紧为 `10`。
若另一枚炸弹也已独立确认阵亡，同一轮传播会继续把其他排除炸弹的历史交换收紧为同军阶对掉。
这使用同一套库存匹配与历史关系，无需为各军阶分别编写特例；师、旅、团、营长各有两枚，
连、排长和工兵各有三枚，必须通过其他已知存活或阵亡记录占满该军阶的全部名额。
司令仍可能在场时，吃掉师长的敌子还可能是司令；攻击未排除地雷的静止敌子失败，也不能确认军长。

`game.mutual_removal_history(viewer)` 返回该观察者目前对历史交换的判断：`ambiguous`（未决）、
`bomb`（涉及炸弹）或 `equal_rank`（同军阶对掉），以及仍可行的身份组合。仅仅知道现在炸弹全部阵亡，
不能把此前交换一律改成对掉：其中某次仍可能就是炸弹的阵亡事件；只排除一方的炸弹也不能排除另一方。
玩家出局保留原有阵亡记录与关联，不会重新给历史死亡分配真实棋种。

这些新结论只影响当前及后续观察，已经采样的旧策略 token 不改写，避免未来证据泄漏。
关系随 clone、环境子进程及训练池存档保存，不受历史窗口截断影响；库存知识格式为 v3，
同时保存每个观察者的已确认棋子编号及已使用槽。导入单独的 v1/v2 棋局时，可从当前公开知识
初始化编号；v1 缺失的旧交战关联不会从裁判隐藏身份补造。旧策略历史不能直接续训。
目前保存的是同归于尽关联，尚非包含所有胜负交战关系的完整联合求解器；固定点传播也不保证找出
全部全局推论，因此仍可能保留尚未排除的候选，不会把不确定性伪装成确定身份。
384 维是可训练投影，不保证无损，也不能单凭编码通过测试就认定棋力提升。

## MAPPO 信息边界

沿用 PPO 的裁剪策略目标与 GAE，改为集中式价值学习：

- Actor：只读取 `GameHistory` 中该玩家可见的棋盘与历史；未知棋子仍是未知。
- Critic：读取独立 `CentralizedHistory` 中所有棋子的真实身份、真实盘面和公开规则状态。
- 环境进程分别返回私有观察和全知观察；两者使用独立数组和历史标识。
- Actor 的采样、似然计算、训练入口与学习图拒绝标记为全知的输入。
- 网页对弈和棋力评测只加载 Actor 与布阵网络，推理时不需要 Critic 或全知历史。

这遵循 MAPPO 的集中训练、分散执行思路；具体实现保留本项目的轮流行动、队伍胜负和历史对手机制。
方法参考：[The Surprising Effectiveness of PPO in Cooperative Multi-Agent Games](https://arxiv.org/abs/2103.01955)。
论文结果不等于本项目新架构的棋力或收敛速度验证。

## 单 V 的回报与 GAE

和棋对两队均为 `-0.15`，因此单个 V 不能在轮到对手时直接取负。
本实现对每个状态，用**同一个单输出网络**分别估计固定队伍 0 和固定队伍 1 的回报。
这是两次不同视角的估值，不是两个输出头。固定视角分别使用座位 0、1，视角座位被淘汰后仍然保留。

对每个队伍独立计算：

```text
delta[t] = reward[t] + gamma * (1 - terminal[t]) * V[t+1] - V[t]
A[t]     = delta[t]  + gamma * lambda * (1 - terminal[t]) * A[t+1]
```

随后为每个实际行动选择所属学习队伍的 advantage 和 V target：

- 军旗奖励保留：扛掉敌旗 `+0.2`，己方或队友旗被扛 `-0.2`，与终局奖励相加。
- 炸弹实际炸掉司令、军长、师长的初始单步奖励分别为 `+0.03`、`+0.01`、`+0.003`。
  主动攻击和对方撞炸弹都算，奖励只给炸弹所属队伍，每次爆炸结算一次；其他子力不加分。
- 和棋惩罚对两队都为负；终局才切断 GAE，采样批次结束使用全知状态 bootstrap。
- 冻结历史模型的回合连接轨迹，但不产生它的 Actor 梯度。
- 现有重复送子惩罚仅记入实际行动的学习队伍，不转换成对方的正奖励。
- 布阵仍使用整局终局奖励。

重复送子初始扣 `-0.01`：同一敌子已有历史碰子证据、曾吃掉自己可确认等级的棋子，
本次又用不高于该已阵亡棋子等级的普通子攻击，且实际攻击失败，才触发。
证据随存活敌子移动，死亡后清除，并按每个观察者各自可见的信息记录和保存。
首次试探、攻击尚未碰过的子、等级更高而胜负未知的攻击、炸弹换子、工兵探雷/排雷，
以及走到空位拦截、堵路、卡位等非吃子动作都不扣分。

这四项都在总训练步数的 **50%** 处归零。三项炸弹奖励按
`初始值 × max(0, 1 - 当前全局环境步数 / 总环境步数的一半)` 线性衰减；
负奖励沿用现有进度衰减及重复送子频率 EMA 的额外衰减，频率下降后系数不反弹。
系数在每个采样批次开始时确定，跨半程的批次会被切开；多卡不足一个同步波次时提前归零。
默认 30 亿环境步配置在 **15 亿步** 起不再给这四项奖励。军旗奖励和终局奖励不受此日程影响。

炸弹的实际伤亡身份只通过训练奖励通道结算，不加入 Actor 的观察或私有历史。
日志中的 `training/bomb_*_reward` 与 `training/futile_attack_penalty` 是当前批次实际系数；
`rollout/bombed_*`、`rollout/bomb_reward_sum` 与 `rollout/futile_attacks` 记录事件数及奖励总量。

每个真实 `game.step()` 只计一个环境步、保存一个训练样本。
两队的 Critic 前向估值不增加环境步数；现有 30 亿步预算口径不变。

## 配置与断点

新配置的关键字段：

```yaml
models:
  four_player:
    action_embedding_dim: 128
    action_encoder_type: coordinates_player_countdown_active_linear
    board_embedding_dim: 384
    board_encoder_type: whole_board_inventory_multihot_linear
    transition_token_dim: 512
    token_fusion_hidden_dim: 512
    temporal_layers: 16
    attention_heads: 8
    temporal_ffn_dim: 1024
ppo:
  algorithm: mappo
  critic_layers: 16
runtime:
  output_root: runs_expand_mappo
```

以后明确要开始训练时，可使用下面的命令；本次未执行：

```bash
python -m junqi.training.cli --mode four_dark \
  --config configs/expand_mappo_training.yaml --model-scale main --device cuda
```

默认新目录为 `runs_expand_mappo/four_dark/with_dead_rules`；双明使用自己的目录。
`--tiny` 缩小为棋盘 48、动作 16、主干 64 维用于测试，仍走新库存编码。二人模式保留 GRPO。
库存编码要求开启确定性阵亡规则。YAML 的 `models.policy.board_encoder` 和四国覆盖配置均使用
`whole_board_inventory_multihot_linear`；模型配置不再提供旧编码开关。所有训练与推理新局在第一步前
启用候选追踪，数组、增量缓存、进程传输和存档恢复均携带候选槽。

新的联合行动编码模型写入 **v16** 断点，保存单 V 的 Critic、独立优化器、私有与全知历史、库存约束、
Critic 棋子独立槽编号及 RNG。全知库存历史标记为 `referee_global_inventory_instances_v2`；
旧的同类多热全知历史或缺少棋子编号的断点不能直接续训，以免混用编码语义。
恢复时检查算法、棋盘编码、动作宽度、层数、注意力头数和融合配置。
六维行动输入的对应模型写入 v15。v11/v12 的已确认棋子仍使用同类多热，v13/v14 未从其他
位置排除已确认编号；虽然参数形状相同，编码语义已经不同，不能直接续训或作为当前 Actor
读取，应建立新运行目录。历史编码标记为 `confirmed_exclusive_slots_v2`。
只接受当前编码的 v15、v16 权重。旧棋盘编码、缺少候选掩码的历史及缺少库存状态的棋局池
会直接报错，不再补列、迁移或回退到旧编码；不能用参数形状相同判断编码兼容。

同架构旧断点若尚未采用炸弹奖励，恢复时需一次性加 `--adopt-bomb-rewards`。
迁移只影响后续 MAPPO 单步奖励，保留权重、优化器、RNG、棋局池、布阵样本及累计步数，
衰减进度不重置；下次普通恢复无需再加。若同时改动已有送子惩罚或其预算，
也需相应的 `--adopt-futile-attack-penalty`。新建运行直接读取新配置。

新配置沿用现有采样规模及历史冠军评测日程。512 维网络的显存占用与吞吐没有实测，
原有 4090 性能数字不能直接用于本分支的工期预测。
