# 布局样本队列与计算优化

布局样本来自完整对局的终局结果。此前每轮新增约 1,000 条，却固定消费 64 条且无限保留，导致更新使用数百轮前的旧数据。此改动保留模型结构、奖励规则、已有参数、Adam 状态和训练步数。

本机四暗配置使用容量 8,192 的环形缓冲，仅保留行为版本距离当前不超过 8 次更新且在当前规则迁移之后的数据。过期和容量淘汰只依据版本与入队顺序，不依据胜负；原始旧队列保留在维护前检查点中。每轮消费所有可用样本，最多 2,048 条；不足上限但至少有两条时也更新。其余配置的容量和年龄可单独调整，年龄 0 表示禁用年龄淘汰。未指定时 PPO 的年龄上限为 16，二人 GRPO 默认禁用年龄淘汰，避免长对局跨越多轮更新时被误当成过期数据。

缓冲在内存中使用紧凑 NumPy 记录，不为已结束样本保留 PlayerSetup 棋盘对象。检查点仍使用原有布局记录格式，兼容旧检查点；恢复时先按版本过滤，再保留有界数据。新增和消费累计计数与队列共同保存。

训练时 25 个目标落点均已知，可以预构造每一步之前的局面，将前缀合批输入网络。每个前缀仍独立进行 26 个 token 的注意力计算，无法访问未来落点。合法掩码、温度 0.7、旧动作概率和奖励目标保留。布局的无填充注意力直接使用 SDPA，避免构造不必要的填充掩码。

CUDA 开启采样图且无 dropout/激活检查点时，新布局生成也复用固定 25 步的 CUDA Graph。每次调用在图外生成独立均匀随机数，通过合法概率的逆累积分布采样；图的预热与捕获不额外消耗随机数。CPU 与其他配置保留原路径。模型拷贝和设备迁移清除图缓存，缓存最多四个形状。采样仍服从分类概率分布，但不承诺与此前 multinomial 实现生成逐局完全相同的随机轨迹。

奖励优势先在完整优化器批次上归一化，再按 32 个布局分块累积加权梯度，最后执行一次梯度裁剪和 Adam 更新。分块不会分别归一化奖励。整批同奖励时任务优势为零，仍保留原先的熵与 KL 约束，同时明确报告零优势。

监控指标包括 `layout/enqueued`、`consumed`、`expired`、`overflow`、`buffer_remaining`、`sample_age_p95`、`sample_age_max`、`zero_advantage_batch` 和 `optimizer/layout_samples`。过期清理不计入已训练样本，消费量也不计入环境步数。

验证使用 CPU 输出/梯度等价测试、真实检查点恢复和独占 RTX 4090 对比。布局性能比较必须使用同一检查点、相同样本与优化器次数；整轮时间同时报告实际 Policy、Critic 和布局工作量。增加样本覆盖的正式方案与纯计算等价加速分别报告，不将样本淘汰算成训练加速。
