# 30 亿步：总环境交互的工程预算

revision 19 起，四国 PPO 的默认 30 亿步统一表示 **累计训练 environment transitions**：
模型选出游戏动作，环境实际执行，状态从 `s_t` 变为 `s_(t+1)`，计 1 步。
预算包含采样对局和所有实际运行的模拟分支，不局限于最后保留的主线。

```text
总训练环境交互 = 基础/采样对局步数 + 额外模拟分支步数
cumulative/environment_plies = cumulative/base_plies + cumulative/continuation_plies
```

## 图中例子的准确计法

从同一局面复制出 8 条分支，每条实际向后执行 32 个游戏动作：

```text
8 × 32 = 256 个 environment steps
```

这 32 步包含该分支的第一个根动作；不能漏掉每条分支的第一步。
即使某些分支动作相同、最后没有采用，只要各自实际推进了环境，都计入 256。
如果随后还在原对局另外执行一次动作，则这部分工作合计 **257 步**。
如果直接接续已经执行过的分支状态，没有再次执行动作，则不再凭空加一步。
分支提前终局时按实际步数累加，例如 `31 + 32 + …`，不补足成假想的 32。

| 操作 | 增加的环境步 |
|---|---:|
| 任一座位执行一次游戏动作 | 1 |
| 一条模拟分支实际执行 N 次动作 | N |
| 8 个并行环境各推进 32 次 | 256 |
| 复制游戏、恢复快照、初始化布阵或 reset | 0 |
| 策略网络推理、Critic 输出 V、边界价值估计 | 0 |
| GAE、反向传播、同批数据学习 3 个 epoch | 0 |
| 重算历史、读取 KV Cache、为四个观察者编码同一步 | 0 |

本预算是训练采样预算。独立模型评测对局的交互和耗时单独记录，不混作 PPO 新增训练样本。
实际执行过的分支即使最后未用于更新，也仍属于训练采样的交互成本。

## 当前 PPO 实现的含义

当前 PPO 用 Critic 和 GAE 估计优势，**没有恢复 GRPO 的 8 条蒙特卡洛终局分支**。
正常对局 rollout 本身就是逐动作推进环境，这些步骤全部计入预算；当前额外分支数为零，
所以此时总交互恰好等于采集的对局动作数。若后续加入实际模拟分支，其每一步也必须计入。

因此，本次修改明确了统计口径，不能给当前 PPO 凭空乘以 8、32 或历史长度，
也不再通过“假想 GRPO 等价采样量”把 30 亿预算缩为约 112 万步。
环境交互数相同，只表示采样规模处于相同工程量级，不保证棋力、样本效率或训练耗时相同。

## 配置、日志、并行和停止

```yaml
ppo:
  target_environment_plies: 3000000000
```

```bash
bash scripts/start_four_player_ppo.sh four_dark --target-environment-plies 3000000000
```

- Python 配置的正式字段为 `target_environment_plies`，计数器为 `environment_plies`。
- `base_plies`、`continuation_plies` 和 `policy_samples` 分开保留，便于核查主线、模拟和学习样本。
- 全部座位、并行对局及 DDP rank 的实际交互求和。30 亿是全局预算，不是每张卡各 30 亿。
- 每个独立训练的四国模式默认各 30 亿；四暗和双明各运行一次，合计预算是 60 亿。
- 当前无额外分支、每轮 5120 步的 PPO 推导出 585,938 轮，单卡尾批 2560 步。
  这只是当前采集结构下的更新数估计；新增模拟时总交互可能提前达到目标。
- 含分支的采集按完整批次完成后检查粗略预算，越过阈值的已执行交互也记录，不截掉计数。
  当前无额外分支的单卡 PPO 可精确停止；DDP 保持各 rank 尾批等长，最多超出 `world_size-1` 步。
- 显式 `--updates` 仍可设置独立的更新次数上限，用于短测试；先达到限制就停止。
- 检查点保存累计计数，恢复后继续累加，不重新从零开始，也不按新定义重复加旧总数。
  旧检查点缺少总量时，从已保存的基础步和分支步相加恢复。未完成更新仍遵循原有原子保存边界。

`--target-continuation-plies` 对 PPO 作为旧名称兼容，映射到总交互预算；对二人 GRPO
保留原来的仅分支预算，以免静默改变旧任务。GRPO 如需相同总交互口径，使用
`--target-environment-plies`。两种预算不能同时指定。

旧 `--grpo-equivalent-plies` 仅保留为显式的历史覆盖规划选项，它不是实际交互计数，
与本次默认 30 亿总交互预算不同，不能同时显式指定。

自动选优使用同一预算口径计算进度。旧 PPO 选优记录只迁移原本命名混淆的字段，
保留已有最优模型和门槛进度。历史性能 JSON 不改写；其无额外分支 PPO 的原始数字仍成立。

## 验证记录

全量测试通过 201 项及 246 个子测试，包含实际 8 条 32 步分支、PPO 测试采集器的额外模拟计数、
多轮优化不重复计步、预算停止、缺少总量的旧检查点恢复和旧选优记录迁移。

另用全新 tiny 模型做了 CPU/Gloo 运行验证，日志与检查点计数一致：

| 运行 | 目标 | 实际总交互 | 基础对局 | 模拟分支 | 结果 |
|---|---:|---:|---:|---:|---|
| 两进程 PPO | 13 | 14 | 14 | 0 | 两轮停止，尾批按 rank 等长多 1 步 |
| 两进程 PPO 续训 | 13 | 14 | 14 | 0 | 恢复第 2 轮，不再采样或重复累加 |
| 单进程 GRPO 总交互入口 | 33 | 33 | 1 | 32 | 第一轮达到总预算即停止 |

这些只验证计数，不预测训练时间或棋力。记录见
[environment_step_budget_validation.json](benchmarks/environment_step_budget_validation.json)。
