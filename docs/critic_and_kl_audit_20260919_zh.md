# expand MAPPO：价值监督缺口、漏防与炸弹优势审计

本记录描述此前固定队伍 GAE 的诊断及两队价值覆盖修复。后续训练已按用户要求进一步改为
[各玩家自己的价值与决策优势](personal_advantages_20260919_zh.md)；下文保留原实验口径，
不把旧两队目标的统计冒称为当前四玩家目标。

本次发现并修复了 Critic 的监督覆盖缺口：GAE 在每一步读取两个固定队伍的价值，但原训练样本只保留当前行动队伍的价值目标。另一队在“对手回合”的估值参与了优势计算，却没有得到同一状态的直接价值监督。这个缺口可以造成局部估值异常，并污染前一步的优势；它不是全部战术失误的唯一解释。

同时按要求将 Actor 的完整 epoch 结束检查阈值设为 KL > 0.10，将学习率下降确认阈值设为 KL > 0.12。下界仍为 0.08，连续确认仍为 3 轮，调整幅度为 5%，调整后观察 3 轮。0.10 < KL <= 0.12 可以停止后续 Actor epoch，但不积累降低学习率的证据。停止阈值不是每个 Adam step 的硬上限。

## 证据来源与边界

- 战术与优势诊断：冻结 update 367，36,077,568 环境步，恢复原有 128 局对局池，使用正式 MAPPO 采样器独立采样 32,768 步。没有调用优化器，没有改写正式断点。
- 完整保留动作、双方旧价值、下一状态价值、双方奖励、原始 GAE 和标准化优势。标准化使用这次 32,768 步诊断批次，不冒称是正式 98,304 步批次的标准化结果。
- 炸弹机会及护旗候选动作根据动作前的公开身份/候选集合识别。裁判信息只供 Critic 和事后核验，未输入 Actor。
- 反事实检查取前 48 个未执行炸大子动作、前 32 个护旗候选，属于有限的确定性诊断样本。一步 TD 不等于完整动作价值或完整 GAE；“吃掉随后夺旗的棋子”也不证明能同时消除其他威胁。
- 本次没有重写奖励或 GAE，没有把赢棋率、KL、拟合误差当作棋力改善证明。

复现脚本与完整数据在 `output/diagnostics/critic_kl_20260919/`：`critic_audit.py`、`critic_audit.json`、`critic_audit_rows.json.gz`、`summarize_critic.py`、`critic_details.json`、`check_critic_state.py`、`critic_independent_check.json`。

## Critic 哪里不正常

原 `team_generalized_advantages` 对两个固定队伍分别计算：

```text
delta_t(team) = r_t(team) + gamma * V_next(team) - V_t(team)
A_t(team) = delta_t(team) + gamma * lambda * A_next(team)
```

gamma=1，lambda=0.95，所有队伍的环境步都在时间轴内；仅整局终止截断。计算后原代码只输出 `value_team` 对应的一个 `value_state/value_target`，而 Critic 优化器也只训练这些样本。所以它只在本队走棋的视角上收到训练标签，GAE 所依赖的对手走棋视角缺失监督。

具体局面（诊断 slot 8，step 210–211，step 从零计）：

1. 队伍 1 在 step 210 夺取一面旗，奖励 +0.2。它的 Critic 旧价值为 −0.9296875。
2. 下一步轮到队伍 0，队伍 0 以 97.4069% 的策略概率选择立即夺旗并结束比赛，双方奖励为 +1.2 / −1.2。
3. 就在这个即将结束的状态，Critic 给队伍 0 **+0.953125**，给即将失败的队伍 1 **+0.61328125**。
4. 队伍 1 上一步的 GAE 因而是 `(0.2 + 0.61328125 + 0.9296875) + 0.95 * (-1.2 - 0.61328125) = +0.0203515625`。实际剩余回报为 −1，相对于当时基线的蒙特卡洛优势是 −0.0703125。这里中间价值的高估与 lambda bootstrap 改变了优势符号。

独立从保存的真实棋局重放 212 步，再用 CPU float32 的普通和 packed 两条路径复算：失败队伍价值分别为 +0.61268812 和 +0.61268818，与原 CUDA bf16 的 +0.61328125 一致到合理精度。因此该案例不是这次检查中的序列打包或 bf16 显示误差。该案例没有找到公开信息下明确可执行的消除夺旗者动作，不把它冒称为“可避免却不防”的证明。

另一个一致性检查：双方未来回报总和只可能因炸大子奖励上升，夺旗与胜负奖励相互抵消，和棋与无效送子降低总和。用全局初始库存给出宽松上界 `4*0.03 + 4*0.01 + 8*0.003 = 0.184`；实际剩余库存及衰减只会进一步降低上界。但 32,768 个状态中有 **19,398（59.20%）** 的双方预测价值之和超过 0.184，14,958 个超过 0.284，最大为 1.89453125。这是模型估值不一致的证据，不应强行通过 `V1=-V0` 修补，因为当前奖励确实不完全零和。

此前整体 Critic explained variance 为 0.8272，但它比较的是行动方估值与同样依赖 Critic 的 GAE 目标，不能证明对手回合估值准确。

## 漏防为什么仍然出现

抽样中找到 75 次这样的决策：军旗在公开观测中已知，当时存在合法动作可吃掉随后夺旗的敌子，但实际没有执行。

| 随后丢旗的结果 | 次数 | 负优势 | 正优势 |
|---|---:|---:|---:|
| 整队立即失败 | 27 | 27 | 0 |
| 只是某位玩家被淘汰 | 48 | 40 | 8 |

这 27 次终局漏防确实受到负优势更新，平均原始优势 −0.3170。负优势是相对于 Critic 基线而言：如果此前已判断接近必败，最后的坏动作未必有很大的额外负优势；单个玩家被淘汰后队友仍可能获胜，也不能要求所有此类样本必为负。

32 个护旗反事实中，Critic 当时给 31 个候选动作正的一步 TD，但这批候选动作的 Actor 概率中位数仅 **0.0248%**。PPO 更新实际采样的动作，推理时也没有拿 Critic 对全部合法动作重新排名。错误动作受罚，不等于正确护旗动作已经得到足够正样本。注意这些反事实 TD 也使用修复前 Critic，不能把它们当作可靠最优动作评价。

## 炸掉大子不一定得到正 GAE

这时炸司令、军长、师长的奖励分别为 **+0.02927845、+0.00975948、+0.00292784**，仍在生效，并随训练在半程归零。实际奖励归属炸弹所在队伍，主动出击和对手撞炸弹都计奖；后者的总次数不能证明模型主动用炸弹。

32,768 步中，公开信息已经足以确认“只能是司令/军长/师长”，且炸弹可以合法攻击的回合有 903 次，实际执行 51 次（5.65%）。机会可能在同局反复出现，也不表示每次炸都是最优。

| 实际炸掉的已知大子 | 次数 | 正 GAE | 负 GAE |
|---|---:|---:|---:|
| 司令 | 34 | 28 | 6 |
| 军长 | 10 | 7 | 3 |
| 师长 | 7 | 1 | 6 |
| 合计 | 51 | 36 | 15 |

师长组只有 7 次，不能用它估计稳定的全局概率。全部主动炸到这三类大子的事件（包括动作前尚不确定身份）有 112 次，其中 33 次负优势。

具体例子（slot 77，step 94）：炸掉已知司令，奖励 +0.02927845，Critic 从 +0.328125 升到 +0.50390625，一步 TD 为 **+0.20505970**；16 步后整队失败，累计 GAE 变成 **−0.59846975**，诊断批次标准化后 **−2.50945**。这一个样本的 PPO 项会压低炸弹动作概率；不能据此断言整个批次净梯度也一定压低它。现有大绝对优势免裁剪机制还会覆盖这个负样本，所以单纯扩大裁剪范围不会修正错误信用分配。

直接炸司令奖励仅相当于这批优势标准差的约 0.123，军长约 0.041，师长约 0.012。奖励为正不保证“很大正优势”；后续败局和 Critic bootstrap 都会影响结果。补齐价值监督能修正其中的估值缺口，但不会让每次炸大子都必然有正优势，也未改变当前终局与战术奖励的权重。

## 已实施的修复

- 保留每步双方各自的旧价值与 GAE 目标。Actor 仍有一个原始公开状态及实际动作样本；另一队目标只供 Critic 使用，不增加环境步数，不进入策略归一化或策略梯度。
- Critic 每个 epoch 覆盖两个视角，包括轮到对手、玩家被淘汰、冻结对手、截断 bootstrap、终局和新局边界。
- 正式每轮 98,304 环境步对应 196,608 个价值标签；价值 minibatch 由 512 个单方标签变为 1,024 个双方标签，仍为每 epoch 192 次 Adam 更新，Critic 仍跑 3 个 epoch。利用历史前缀共享，保持原来的优化步数预算。
- Critic CUDA graph 的价值查询容量改为 1,024，Actor 保持 512；历史 token 容量及溢出回退机制不变。
- 新增双方口径的 `critic/both_teams_*` 指标及价值标签覆盖计数，原行动方指标继续保留以便解释历史数据。
- 模型形状、模型权重、优化器状态、奖励、GAE 参数、对局历史和累计计数都可原样恢复；新增目标只在下一次采样时生成。

回归覆盖双方非零和奖励、冻结回合、终局、淘汰/跨回合、bootstrap/reset、策略信息隔离、双方实际梯度方向、每个 epoch 的标签覆盖、Adam 步数，以及普通/CUDA graph 损失和梯度一致性。选定 Python 回归合计 116 项通过、89 个子用例通过；最后单独复核的 scalar MAPPO graph 和覆盖测试共 13 项通过。KL 前端检查 5 项通过。

KL 修改先从 update 367 完整恢复；首轮 update 368 的 KL=0.11772396，Actor 1 个 epoch/192 次更新，首遍覆盖 100%，Critic 3 个 epoch/576 次更新，Actor 当前与下一轮 LR 均为 1.036282498542962e-5，调整原因 `hold`，证明两个阈值已独立生效。

价值监督修复前再次等待正式训练完整保存 update 373，36,667,392 环境步。隔离恢复逐项验证了四组模型、三组优化器、128 局对局池及历史、学习率控制器、参数配置、计数与 Python/CPU RNG。该断点 SHA-256 为 `30ddd5cca2d013ff637e5062902e28fc17c8c56d13aabeb44690292d04bfa008`，没有重置训练。

## 匹配 GPU 验证

另从 update 373 在隔离目录采样 32,768 个真实动作，对同一冻结批次分别恢复相同 Critic 权重、优化器、学习率和 shuffle RNG，比较原单方训练与修复后的双方训练。两者都是 3 个 epoch、192 次 Adam 更新；Actor、布阵及参考布阵权重逐项保持不变。测试只修改隔离内存中的 Critic，没有写正式检查点。

| 完整计算图预热后的 Critic 训练 | 单方目标 | 双方目标 |
