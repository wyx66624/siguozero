2026-09-19 更新：当前学习率采用 [0.08–0.14 KL 保持区间与双向观察期](expand_kl_band_20260919_zh.md)。本文下方的 50%/40% 调节及小批次 0.1 早停属于启动时的历史配置。

训练目标为 30 亿真实环境步；重复学习一个样本不会增加环境步数。
启动配置：`configs/expand_mappo_training.yaml`，监控配置：`configs/expand_console.json`。

| Actor / Critic 最大 epoch | 3 / 3 |
| Actor 首遍覆盖 | 完整处理全部当前模型样本，随后才允许 KL 早停 |

| Actor / Critic 学习率硬边界 | 下限 5e-6、上限 1e-4；当前 Critic 与 Actor 倍率为 1 |
| 学习率上调 / 下调 | 完整完成 3 个 Actor epoch 且 KL ≤ 0.1 时，下一轮乘 1.5；KL > 0.1 时乘 0.6；均受原上下限约束 |
| 优势裁剪 | 整批标准化；正负优势按绝对值放宽；`abs(A) >= 2` 免除 PPO 比率裁剪 |
| 完整断点写入间隔 | 每跨过 1,000 万步门槛，于当轮完整更新后保存 |
| 冠军评测 | 每 5,000 万步，500 局，挑战当前历史冠军 |
| 历史模型准入 | 所有实际保存步数 >= 5,000 万的兼容模型版本 |
| 历史对战开启 | 10 亿环境步（2026-09-19 调整） |
| 开启后的新局比例 | 50% 当前模型自博弈、50% 历史对手；队友仍为当前模型 |

早停阈值约束重复学习；为满足首遍完整覆盖，不能将 0.1 描述为每次 Adam 更新之后都不会超过的硬上限。
学习率反馈仅使用 KL，未超限且完整完成训练时上调 50%，超限时下调 40%。Clip 探针值和小批次峰值继续记录，但不参与学习率决策。
新配置以完整完成 3 个 Actor epoch 且 KL 反馈未超限为上调依据，
不再要求 KL < 0.01、稳定 5 轮或冷却 5 轮。KL 反馈采用当轮 minibatch 与各 epoch 末探针的最大值，
超过 0.1 时降速；首遍必须完整覆盖，后续 epoch 可在 minibatch 边界提前结束。
每个 epoch（包括提前结束的部分 epoch）记录轮末 probe KL、熵、归一化熵、clip、覆盖比例和优化器步数。
同一训练轮的各 epoch 采用相同的确定性 8,192 条探针，最终探针直接复用于学习率反馈。
各 epoch 的 KL 都相对于本轮采样时的行为策略，不是相对于前一个 epoch。
这种完成情况反馈直接控制实际学习率，不再叠加独立预热增长或余弦衰减；首次切换时保留断点的实际 LR，
后续正常恢复使用保存的下一轮 LR，修改上限也不会放大已有实际 LR。
这里的 clip 指除去免裁剪大优势后的比率越界比例；原有 10% 暂停回升和 12% 下降阈值已删除。
用户要求下限不能过低，学习率下限已由 1e-6 提高至 5e-6；任何学习率反馈都不能突破。
达到下限后如 KL 仍超标，记录为下限约束，不再降低学习率；首遍覆盖要求继续生效。
调整后从第 13 轮继续，并验证到第 15 轮：Actor/Critic 实际学习率均为 6e-6，
运行指标中的下限为 5e-6，首遍覆盖率 100%；记录见 `output/diagnostics/expand_lr_floor_verification.json`。
优势本身没有限幅。冻结历史模型不接受策略梯度，其行动仍保留在环境轨迹中供价值学习与回报传播。
历史阶段会让正在进行的棋局自然结束，再按配额安排新局，不替换半途对手。

历史选择与 `E:\agent\siguozero` 当前 `strength` 配置一致：
对手权重为 `exp(失败率 EMA / 0.1)`，数值实现先减最大值；EMA 系数为 0.01，
新模型初值为 0.5，和棋不更新失败率。所有合格版本始终有非零被选概率，缓存容量不删减候选库。
没有单独的冠军采样配额。主项目旧架构的模型权重不能当成本次扩展架构的对手，本次只复用其概率规则。

## 性能与正确性证据

CPU 剖析发现重复构造库存掩码、转换候选位集和分配已确认棋子槽位的开销较高。
优化使用有界缓存和预计算位掩码，只对新确认棋子分配槽位；新局复用只读棋盘几何。
重放 1,200 步得到的所有玩家观察 SHA-256 在优化前后相同：
`b025d9511aa3d474d7027828cf89fad06271b149f0ba60ee9b7151e35bc2c6eb`。
该重放包含第一次库存优化；后续缓存与几何复用另经规则、库存、真实子进程及回溯测试验证。

相同 128 局、16 个环境进程、每轮 98,304 步、Actor/Critic 各 3 epoch 的 GPU 探针：
优化前第三轮为 110.48 秒；库存优化后第三、四轮为 86.95、84.22 秒。
前两轮包含较多图捕获和编译，不能拿启动速度代表持续速度。
正式启动先验证 2 epoch：首次第 3 轮 81.76 秒，恢复并完成图捕获后的第 5 轮 84.09 秒，
训练本体已接近 30 天，没有充分计入保存、评测和未来历史对手开销。
因此启动阶段曾使用 Actor/Critic 各 1 个完整 epoch，为额外开销预留时间。
随后用户明确要求改回最多 3 个 epoch，并按完整训练情况提高学习率；当前配置已改为 3 / 3。
一遍训练的原工期估算不能直接用于三遍配置；30 亿真实环境步目标保持不变。
编码与吞吐测试不证明棋力提升。

原始证据位于 `output/diagnostics`：
`expand_launch_gpu_g128_w16/benchmark.json`、`expand_launch_gpu_cached_g128_w16/benchmark.json`、
`profile_inventory_before.txt`、`profile_inventory_after.txt` 及 `expand_launch_*pytest.xml`。
正式运行的吞吐、断点恢复及工期估算另记录于 `expand_launch_verification.json`。
30 天的训练本体最低速度约为 1,158 步/秒；总工期还取决于评测、保存、长局比例、历史阶段和停机时间。

## 三个 epoch 与上限 1e-4 的实际恢复验证

用户随后要求恢复每轮最多 3 个 epoch：首遍完整训练，KL > 0.1 后停止剩余训练；
完成全部三遍且保护允许时逐轮提高学习率，直到 1e-4。另一个任务中的新指令把 clip 阈值改为
达到 10% 暂停回升、严格超过 12% 才下降；两项修改共同生效。

正式训练在第 32 轮完整保存后恢复，保留 3,145,728 环境步、128 个未完棋局、模型、
优化器、RNG、库存历史及历史对手控制状态。初次切换实际 LR 保持 1.28e-5。
第 33 轮 Actor/Critic 均完成 576 次更新（各三遍），首遍覆盖率 100%；
三个 epoch 的轮末 KL 为 0.011716、0.018768、0.021394，轮末熵为 2.893399、2.883546、2.864872。
最大小批次 clip 反馈为 10.35%，因此下一轮保持 LR。
第 34 轮也完整完成三遍，但 clip 反馈为 12.70%，下一轮 LR 按保护乘 0.8 降至 1.024e-5。

隔离 GPU 比较确认两种配置使用同一个第 32 轮断点、同一批 98,304 条标准化样本，
样本字段摘要均为 `8c5a11b622b0c022e0dc6383abf0b217436c069756f68a4b33c0ebb806e51422`。
比较未写入正式模型文件。新旧配置实际 LR 分别为 1.28e-5 和 1.32e-5，不能描述成只改变 epoch 的消融。
学习率与训练合同回归 30 项通过，监控展示 4 项通过；正式训练及监控服务均运行。

第 34 轮训练本体 84.28 秒，计入相邻日志边界的间隔为 85.44 秒，约 1,151 环境步/秒。
这是恢复后的首个稳定轮，按此速度剩余训练本体约 30.1 天；尚未计入后续历史对手、冠军评测和停机开销，
不能承诺三遍配置的总工期在一个月内。记录位于 `output/diagnostics/three_epoch_lr_20260918/verification.json`、
`formal_update_33.json` 和 `formal_update_34.json`。
