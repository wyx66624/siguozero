# 四暗 MAPPO 训练吞吐优化

测量日期：2026-09-19 UTC（本地 09-18 晚至 09-19 凌晨）。对象是 `siguozero-expand` 的 RTX 4090 正式模型。

同一 update 157 检查点、每轮 98304 环境步、完整 3 个 Policy epoch 和 3 个 Critic epoch：三轮完整训练基准从 **923.0 步/秒提高到 1375.2 步/秒，提升 49.0%**。预热后的两轮平均从 924.5 提高到 1425.6 步/秒。

## 降速原因

运行日志中，早期完整执行 3 个 Policy epoch 的轮次平均约 1100 步/秒，近期同口径约 967。1300 左右的部分轮次因 KL 提前停止而只执行了一个 Policy epoch，不能直接与完整三轮训练相比。

近期对局变短，每个 98304 步的批次完成对局数从约 224 增到约 390，开局、布局学习和 CPU 环境工作增多。此外，每步重复生成 Actor/Critic 的公共观察；没有新增知识的普通移动也重复求解候选子力；主进程存在 GPU 索引同步等待和频繁循环垃圾回收。

没有发现显存溢出或内存不足导致降批。1000 步历史的固定 KV 分配仍是 15.640625 GiB，本次没有缩短历史。

## 修改

- Critic 复制本步已生成的公共观察，再填入训练专用的全局信息。Actor 数组保持独立；同时复用每位玩家的真实阵亡统计，预计算阵亡槽序号。
- 普通非战斗移动只有在所有玩家的候选集合均未变化时，才跳过重复库存求解。位置及确认子力编号照常移动；首次获得新信息、工兵转弯、战斗等仍走完整推理。
- 固定 KV 推理的索引通过锁页内存异步传入 GPU，消除直接从 Python 列表构造 CUDA 索引造成的额外主机等待。
- MAPPO 采样期间保留引用计数回收，将循环垃圾回收集中到采样结束。异常时也恢复原 GC 状态。
- 直接构造 Critic 状态，减少临时对象；归一化后释放原始样本，训练完成后释放已消费批次，避免下一轮继续保留它们。
- 环境进程消息改用不可变命名元组，字段及默认值保持一致，减少反序列化时逐字段反射和赋值的开销。该消息不属于检查点格式。

模型结构、128 局并行、16 个环境进程、98304 步更新量、1000 步历史、epoch 上限、KL 条件、学习率及全部奖励配置均未改变。配置 SHA-256：`7a7a71adb69f2421ff3ed0bc809fd1b4730d3b00288b7ab51ddd81169c3898a4`。
