## 五维坐标的准确含义

历史动作的主视角起终点编号仍遵循既有 129 点/60 点协议，持久化仅保存三个整数
`(from_code,to_code,relative_actor)`。构建模型输入时，把两个点编号无损转换成
统一的全盘二维坐标；不能直接使用每个阵地内部的 `(row,column)`，否则不同阵地会重码。

坐标轴为：`+x` 向观察者右侧，`+y` 从观察者向棋盘远方。所有坐标都是原始整数，
写入 float32 五维张量后直接投影。

四国阵地的局部行列仍取 `row=1..6`、`column=1..5`。令：

```text
u = column - 3
v = -(row + 2)
```

| 原有点位区间 | 阵地 | 全盘坐标 (x,y) |
|---|---|---|
| 0..29 | 自己 | (u,v) |
| 30..59 | 左侧 | (v,-u) |
| 60..89 | 对面 | (-u,-v) |
| 90..119 | 右侧 | (-v,u) |
| 120..128 | 中央九宫 | (2×(column-2), 2×(row-2))，中央行列为 1..3 |

四国坐标范围是 `[-8,8]`，中央九宫横纵坐标各为 `{-2,0,2}`。129 个点的二维
坐标全部唯一；切换主视角相当于整数倍 90° 旋转，不改变原有点位规则。

二人棋盘没有中央九宫：令 `u=column-3`、`v=-row`，自己阵地为 `(u,v)`，
对手阵地为 `(-u,-v)`。两个阵地共 60 个坐标唯一，切换观察者相当于 180° 旋转。

行动方直接沿用当前 `ObservedEvent.actor` 的相对编号：

- 四国：自己 0、相对玩家 1、对家 2、相对玩家 3。
- 二人：自己 0、对手 1。棋盘子力中“对手精确身份使用块 2”不改变此动作字段的 0/1 约定。

例：四国相对玩家 3 从点 0 移动到点 120：

```text
原始动作记录：(0,120,3)
模型动作输入：[-2,-3,-2,-2,3]
```

## 初始 token、历史与棋盘

每局初始 token 的动作分量严格为全零。动作不存在时，presence mask 在投影前屏蔽
填充值，在投影后屏蔽 bias，确保没有“可训练的无动作占位”。后续每手使用本手动作
与该动作完成结算后的可见棋盘。原有局面元数据在 concat 后叠加，再进入时序网络；
在场方和已亮旗方等局面状态与本次删除的动作事件计数字段是不同输入。

整盘 `Linear(18009,256)`、主模型的 32 层时序网络和合法动作输出协议继续使用。
棋盘类别仍根据当前观察者的可见身份生成。规则结算产生战果，动作编码器不读取战果字段。

## 参数与检查点

动作编码器由 **150,272** 个参数降为 `5×256+256 = 1,536` 个参数；Policy/Critic
各减少 **148,736** 个参数。它在整套网络中的占比很小，不能把该模块的压缩比例当作
整个训练流程的加速比例。后续已对 revision 21 重新测量四暗、双明各 20,480 步，
各卡 30 亿步的条件估算见[新动作编码训练时间](action_linear_training_eta_zh.md)。

当前使用格式 **6** 检查点、格式 **5** 基础游戏池，并在玩家历史中标记
`action_encoding=coordinates_player_linear`。格式 5 模型的旧字段 Embedding 权重
与新层不兼容；恢复、推理和 `--init-from` 会明确拒绝旧模型格式。
切换架构需要新的训练目录，已有权重文件不转换或覆盖。
