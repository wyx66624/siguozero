## 已验证的计算改动

- Critic 批次需要超过四个固定长度 CUDA Graph 子批次时，使用已有的变长 packed 计算。完整样本、损失权重、梯度累积和一次 Adam 更新保持一致。
- 最后一层注意力计算仍保留完整因果历史；逐 token 的输出投影、残差与 FFN 移到查询位置提取之后。重复查询的梯度仍累加，零权重 padding 不产生训练信号。
- Actor 转入 Critic 时释放未使用的 CUDA allocator 缓存，保留存活张量与图存储；释放耗时计入 Critic 时间，并记录释放量。
- 新增 Critic 计划图子批次数指标，便于区分实际工作量变化和执行速度变化。

固定真实样本来自 update 3943，四批各 4096 个价值标签，包含约 2.24万、2.60万、3.05万和 3.63万唯一历史 token。诊断不更新正式模型、不写正式检查点。以下每个批次都执行与正式路径相同的梯度裁剪与指标同步，避免把异步提交速度当作训练速度。

| 固定批次 | 原 4096-token 图路径 ms | 新路径复测 ms | 耗时降低 |
| --- | ---: | ---: | ---: |
| 0 | 96.12 | 81.85 | 14.85% |
| 1 | 110.54 | 91.30 | 17.40% |
| 2 | 128.23 | 103.91 | 18.97% |
| 3 | 154.16 | 121.48 | 21.20% |

合计耗时降低 18.51%；这是固定 Critic 样本的结果，不能直接当作完整训练周期的提升。

数值边界：CUDA BF16 改变分块大小并非位级等价。固定第 1 批中，原图路径与变长路径的 loss 约为 0.0055372 / 0.0055646，裁剪后梯度相对差异约 7.25%；同一变长路径重复执行也有约 0.56% 的梯度差异。独立 CPU 对照验证的是相同目标及加权梯度的数学实现，不代表后续参数轨迹或棋力完全相同。本次没有进行棋力对照评测。

缩小到 8/16 个历史序列以及放宽单个前缀链样本数没有获得更好结果，未用于正式训练。16K 图候选未通过所设的数值比较门槛，未采用。

`max-autotune-no-cudagraphs` 的整批复测同样没有加速：四批约 82.17 / 91.25 / 103.80 / 122.43 ms，对照默认编译的 81.05 / 90.78 / 103.18 / 119.62 ms。第 1 批梯度相对差异约 4.03%，也大于本次采用门槛。保留原 `compile_mode: default`，没有修改训练配置。
