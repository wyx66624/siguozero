# 策略状态、棋盘快照与转移 Token 编码规范

版本：0.7（revision 22：四国棋盘与动作各 128 维）  
适用棋盘编码：`board_encoding_zh.md` 0.2  
适用动作编码：`action_encoding_zh.md` 0.1

本文以 `d` 表示单个棋盘/动作向量宽度：四暗、双明 `d=128`，二人 `d=256`。
转移 token 宽度为 `2d`。四国 main 的时序网络为 32 层、FFN 1024；历史长度和编码含义不变。
配置由 `models.four_player` 覆盖所选模型规格，tiny 测试规格单独定义。

## 1. 范围与信息边界

本规范定义策略模型在一次决策时看到的时序输入：

```text
Initial State Token + Transition Token 1 + Transition Token 2 + ...
```

“看到整个棋盘”是指看到**当前玩家按规则可见的全棋盘占位快照**，不是看到裁判状态中的全部暗子身份：

- 自己的棋子显示精确类型。
- 四暗模式下，上家、对家盟友和下家的棋子在身份尚未确定时只显示所属相对座位。
- 双明模式下，对家盟友从开局起显示精确类型；两侧敌人在身份尚未确定时只显示所属相对座位。
- 二人暗棋中，尚未确定身份的对手棋子统一显示为对家未知棋子。
- 一旦某位玩家能仅凭其可见信息和规则唯一确定一枚存活棋子的身份，环境就为该玩家持久记录该结论；以后每张棋盘快照直接使用“相对座位 + 精确棋种”码，不依赖早期事件仍在 1,000 步上下文内。
- 每个时刻还携带该玩家已经**确定知道阵亡**的其他玩家棋子先验；不唯一的猜测和仍存活的推断身份不能写入阵亡位。
- 裁判真实身份只用于战斗结算和模拟，绝不能进入棋盘向量、动作嵌入、合法动作 mask 或模型标签。

四个/两个座位分别维护自己的 token 序列。每次全局动作完成后，环境按每名玩家自己的主视角生成“动作 + 动作后棋盘”，因此同一物理局面在不同玩家序列中的整数码可以不同。

“分别维护序列”不表示分别加载模型：一个训练模式只实例化一个 Policy 和一个 Layout，所有座位把各自的序列送入同一个共享网络，参数与显存不按座位复制。

本规范的确定性推断与阵亡先验受同一个 `dead_rules_enabled` 开关控制。开启时使用下述完整定义；关闭时不创建 `known_identities` 结论、不在历史记录中保存阵亡向量，Policy 也不实例化 75 维投影/融合参数。关闭态仍显示信息模式原本公开的身份（自己、双明盟友、已亮军旗）。两种结构必须分别训练和保存，详见 [死规则特征开关与消融训练](dead_rule_ablation_zh.md)。

## 2. 全棋盘整数向量

### 2.1 顺序与长度

对玩家 $i$，动作后时刻 $t$ 的棋盘链为：

$$
B_t^i=[c_t^i(0),c_t^i(1),\ldots,c_t^i(N-1)].
$$

- 四国军棋：$N=129$，严格按主视角点编码 `0..128` 排列。
- 二人军棋：$N=60$，严格按主视角点编码 `0..59` 排列。
- 每个整数只说明该点当前可见的占用/子力类别。
- 二人和四国样本合批时使用显式 point mask；不得用 `0` 把 60 点补到 129 点，因为 `0` 表示真实空点。

例如：

```text
[32, 1, 2, 40, 0, ...]
```

表示编码 0 是我方工兵，编码 1 是上家未知棋子，编码 2 是对家未知棋子，编码 3 是我方司令，编码 4 是空点。若上家工兵的身份已经确定，第二个码应从 `1` 改为 `64`。

### 2.2 基础占位码

| 整数码 | 含义 |
|---:|---|
| `0` | 空点 |
| `1` | 上家的一枚未知类型棋子 |
| `2` | 对家的一枚未知类型棋子；四国中对家是盟友，二人中对家是敌方 |
| `3` | 下家的一枚未知类型棋子 |

“上家/下家”按当前规则配置中的行棋顺序定义：

- 上家：在开局固定行棋顺序中紧邻当前玩家之前的原始座位。
- 下家：在开局固定行棋顺序中紧邻当前玩家之后的原始座位。
- 对家：物理座位正对面的玩家。

编码器必须通过开局固定座位关系函数求这三类，不能把 `1/3` 永久硬编码成屏幕左/右，也不能按棋子当前所在的棋盘区域推断归属。玩家出局后，棋子所属关系仍按原始座位计算，不随跳过回合而改码。

二人军棋不存在 `1` 和 `3`，对手占位只使用 `2`。

### 2.3 我方精确子力码

| 我方棋子 | 整数码 |
|---|---:|
| 军旗 | `30` |
| 炸弹 | `31` |
| 工兵 | `32` |
| 排长 | `33` |
| 连长 | `34` |
| 营长 | `35` |
| 团长 | `36` |
| 旅长 | `37` |
| 师长 | `38` |
| 军长 | `39` |
| 司令 | `40` |
| 地雷 | `41` |

这些整数是稳定类别 ID，不是可直接参与大小比较的连续军阶数值。战斗仍由规则引擎按棋子枚举类型结算。

### 2.4 已确定身份的相对座位码

任何按规则可见或已经可靠推断出的精确身份统一使用无碰撞的相对座位分块。设棋种的我方基础码为 $b(k)\in[30,41]$，相对座位块为 $r$，则：

$$
c(k,r)=b(k)+32r.
$$

四国模式中 $r=0,1,2,3$ 分别表示我方、上家、对家和下家。各块为：

| 相对归属 | 精确码区间 | 军旗 | 工兵 | 军长 | 司令 | 地雷 |
|---|---:|---:|---:|---:|---:|---:|
| 我方 | `30..41` | `30` | `32` | `39` | `40` | `41` |
| 上家 | `62..73` | `62` | `64` | `71` | `72` | `73` |
| 对家 | `94..105` | `94` | `96` | `103` | `104` | `105` |
| 下家 | `126..137` | `126` | `128` | `135` | `136` | `137` |

这保留了“我方/上家/对家/下家工兵分别为 `32/64/96/128`”的约定。不能把所有基础码直接乘以 `1/2/3/4`，因为那会产生碰撞，例如“对家司令 `40×3`”和“下家军旗 `30×4`”都会等于 `120`。固定步长 32 能保证 48 个“座位 × 棋种”类别全部唯一。

特殊模式约定：

- 四暗中，身份未确定的上家/对家/下家仍分别使用 `1/2/3`；身份确定后换为对应精确块。
- 双明中，对家盟友从开局起使用对家块 `94..105`；两侧敌人在身份未确定时仍使用 `1/3`。
- 二人棋盘上的唯一对手在物理上是对家：未知时使用 `2`，身份确定后使用对家块 `94..105`。
- padding 类别固定为 `138`，棋盘类别词表大小为 `139`；全部码仍可无损保存为 `uint8`。

### 2.5 持久精确推断与死规则枚举

本节仅在 `dead_rules_enabled=true` 时执行。

环境按观察者分别维护 `known_identities[viewer]`，并对每次战斗枚举该观察者看来仍合法的 `(进攻棋种, 防守棋种)` 组合。枚举只使用模式可见身份、以前已经确定的身份、公开候选集合、公开战果、行棋几何、亮旗事件和确定阵亡库存；只有当所有合法组合对某个存活方给出同一棋种时才写入。当前实现因此覆盖且不限于：

1. 司令阵亡后，该方军旗亮出；存活军旗立即使用对应精确码。
2. 某枚棋子吃掉观察者已知的军长且进攻方存活，则该进攻棋子一定是司令。
3. 某枚棋子在铁路一步中完成非直线换线，则它一定是工兵。
4. 观察者已知的司令主动攻击后阵亡、守方存活，则守方一定是地雷。
5. 已知/由转弯确定的工兵进攻并存活，且不是夺旗，则被吃掉的守子一定是地雷。
6. 某方已经亮旗，即其唯一司令确定阵亡；该方棋子吃掉观察者已知的师长并存活时，进攻子一定是军长。
7. 双方同归于尽且只有一方在本手新亮旗，新亮旗方阵亡子是司令，另一方阵亡子是炸弹；双方都在本手新亮旗时是司令对司令。
8. 已知地雷或军旗在双方同归于尽中被消灭，另一方只能是炸弹。
9. 已知普通军阶与对手同归于尽，而对手的炸弹已被公开布阵限制或确定阵亡库存排除时，对手只能是同军阶。例如从未移动过的本阵第一排棋子不可能是炸弹。
10. 某棋种的全部初始数量均已确定阵亡或以确定身份存活在别处时，会从其他暗子的候选集合中排除；由此产生的新单例继续按同一唯一性原则记录。

确定身份附着在棋子上：棋子移动时结论跟随到终点；棋子被消灭或玩家出局时删除。司令揭旗和铁路转弯属于所有玩家都可由公共事件确定的事实；“吃我方军长”和“已知司令撞雷”则按观察者当时是否已知相应棋子身份分别判断，不能把一名玩家的私有结论泄露给其他玩家。

`candidate_mask` 仍可保存更宽的公开候选集合，但只有候选集合缩为单例或上述组合枚举得到唯一答案时才写精确棋盘码。实现会在内部用真实身份做“结论不得矛盾”的断言，但真实身份绝不参与候选筛选；交换两份对该玩家不可见的暗子身份，不得改变其输入。

本码表无损覆盖当前训练的四国 `four_dark/double_open` 和二人 `dark`。码表 0.3 与旧版双明 `60,62,...,82` 的乘二语义不兼容；载入旧检查点必须失败关闭，不能复用含旧棋盘 embedding 的权重继续训练。

### 2.6 确定阵亡棋子先验矩阵

本节输入仅在 `dead_rules_enabled=true` 时存在。关闭时不是 25/50/75 位全零，而是该字段为 `None` 且 collator 不分配规范 75 维张量。

每名被记录玩家固定使用 25 个二值槽，槽位顺序与布局 Decoder 的固定生成顺序完全相同：

```text
[军旗,
 地雷, 地雷, 地雷,
 炸弹, 炸弹,
 司令, 军长,
 师长, 师长, 旅长, 旅长, 团长, 团长, 营长, 营长,
 连长, 连长, 连长, 排长, 排长, 排长, 工兵, 工兵, 工兵]
```

对观察者 $i$ 和另一玩家 $p$，定义：

$$
D_t^{i,p}\in\{0,1\}^{25},\qquad
D_t^{i,p}[m]=1
\Longleftrightarrow
\text{第 }m\text{ 个规范库存槽已被 }i\text{ 确定知道阵亡}.
$$

同类多枚棋子在暗棋中没有可公开区分的实例编号，因此采用规范一元计数：若已确定阵亡两枚地雷，就把三个地雷槽中的前两个置 1，而不是臆测它们对应哪个初始位置。初始全部为 0；一个仍存活但身份已经推断出的棋子只写入棋盘精确码，不能提前写入阵亡矩阵。

记录的行数和相对座位顺序为：

| 模式 | 原始保存形状 | 行顺序 |
|---|---:|---|
| 四暗 | `3 x 25 = 75` | 上家、对家、下家 |
| 双明 | `2 x 25 = 50` | 上家、下家两名敌方；自己与对家盟友不占行 |
| 二人暗棋 | `1 x 25 = 25` | 唯一对手 |

双明中自己与对家盟友共享 `known_identities` 和确定阵亡信息。模型合批时使用统一 75 维相对座位槽：四暗为 `[D_上;D_对;D_下]`，双明为 `[D_上;0_25;D_下]`，二人为 `[0_25;D_对手;0_25]`。这只是内部规范化，不增加时序 token 数。

阵亡位同样遵循“全部合法组合一致才提交”的原则。可直接置位的情形包括：模式本来可见或先前已确定身份的棋子阵亡；上述死规则唯一确定死亡身份；司令死亡亮旗；夺旗/玩家出局后该玩家完整 25 子均已离场。若双方同归但仍可能是“炸弹对任意子”或“相同军阶对碰”中的多个答案，则不置任何不确定棋种位。

## 3. 整张棋盘通过一个线性层映射为 d 维

revision 20 使用 `WholeBoardEncoder`。按玩家视角的 `point_code` 顺序保留原始
60/129 个整数类别码；在模型入口把它们展开为一个固定长度的整盘类别向量。
类别展开不含可训练参数，也不生成每点神经表示。

```text
整盘向量 = [按点位顺序排列的类别 one-hot；模式 one-hot；可选的规范阵亡位]
棋盘向量 = Linear(整盘向量) → d 维
转移 token = concat(动作向量 d 维, 棋盘向量 d 维) → 2d 维
```

- 棋盘部分：`129 × 139 = 17,931` 维。每个真实点只有其类别位置为 1。
  二人棋盘只占前 60 个点槽；其余点槽全零。真实空点仍激活类别 0，与填充区分。
- 模式部分：3 维 one-hot，区分四暗、双明和二人。
- 死规则开启：拼入规范化的 75 个阵亡位，总输入 `18,009` 维。
- 死规则关闭：不创建阵亡张量，也不创建对应的投影输入列，总输入 `17,934` 维。

整个向量只经过**一个可训练线性投影**，没有逐点 Embedding、棋盘 Transformer、
图注意力、汇聚 token 或单独的阵亡投影/融合网络。位置通过固定向量槽位表达，
类别编号不按连续军阶数值解释。道路/铁路规则继续由裁判和合法动作 mask 执行。

原始历史仍保存棋盘整数链和可选阵亡位；learner 用当前权重计算整盘投影。
采样期的整盘向量缓存、时序 KV 缓存，以及同次学习的历史前缀合并继续使用。
当前格式 6 检查点同时标识整盘线性编码和五维动作编码；格式 4/5 权重不能直接继续训练。
格式相同也必须满足模型维度相同；旧四国 512 维时序权重不能直接加载到新 256 维结构。

## 4. 动作嵌入为 d 维

动作的稳定身份仍是主视角有向二元组：

```text
action = (from_code, to_code)
```

历史只记录 `(from_code,to_code,actor)` 三个整数。在模型入口，将已有主视角点编号
无损转换成整张棋盘的二维坐标，构成五个数值：

```text
[source_x, source_y, destination_x, destination_y, relative_actor]
  → Linear(5,d) → 一个 d 维动作向量
```

不使用字段 Embedding、one-hot、LayerNorm 或战斗结果相关字段；单个动作编码器共
四国 768 个参数，二人 1,536 个参数。行动方沿用观测中的相对玩家编号：四国为 0..3，二人为 0/1。
这与二人棋盘子力编码将对手放入精确身份块 2 是不同的字段约定。
二维坐标规则、中央点及主视角变换见[五维动作编码](action_linear_zh.md)。

$$
q_t=W_a[x_{from},y_{from},x_{to},y_{to},actor]^T+b_a\in\mathbb R^{d}.
$$

战斗结果、是否攻击、被夺军旗归属、新亮旗数量和出局人数均不进入动作输入。
动作执行后的可见棋盘仍由环境完成结算后产生。

## 5. 2d 维初始与转移 token

### 5.1 初始棋盘 token

布阵完成且尚未走第一步时，先编码玩家可见的初始棋盘 $B_0$：

$$
T_0=[\mathbf 0_d;g_0]\in\mathbb R^{2d}.
$$

前 d 维是严格的全零动作占位，后 d 维是初始棋盘嵌入。投影 bias 也会被动作
presence mask 清零，不能换成学习的“无动作”向量。此处指原始 concat；后续叠加
位置、模式和局面元数据后，完整 Transformer 输入的前 d 维不要求保持为零。

### 5.2 动作—棋盘转移 token

执行第 $t$ 个动作并完成战斗、移除、公开和轮转结算后，先生成**动作后的棋盘** $B_t$，再构造：

$$
T_t=[q_t;g_t]\in\mathbb R^{2d},\qquad t\ge1.
$$

顺序固定为“动作嵌入在前、棋盘嵌入在后”。不能使用动作前棋盘，也不能把两个 d 维向量相加。

因此序列语义为：

```text
[零动作 + 初始棋盘]
[动作 1 + 动作 1 后的棋盘]
[动作 2 + 动作 2 后的棋盘]
...
```

## 6. 1,000 步上下文

初始 token 永远保留。决策第 $t+1$ 步时，策略输入为：

$$
S_t=[T_0,T_{\max(1,t-999)},\ldots,T_t].
$$

这表示：

- 最多保留之前 1,000 个动作—棋盘转移 token；
- 再额外固定保留一个初始棋盘 token；
- 时序 Transformer 的最大序列长度为 `1001`；
- $t<1000$ 时不补造历史，只使用实际存在的前缀；
- 因果 mask 保证任何位置看不到未来动作或未来棋盘。

当第 1,001 个转移到来时，只淘汰最老的转移 token，`T_0` 不淘汰。开启死规则时，当前完整可见棋盘与确定阵亡先验始终融合在最后一个 token 的后 d 维；已确定的存活棋子也会在最新快照中继续使用精确码。因此历史滑窗移走原始战斗事件后，模型仍不会忘记该确定信息。关闭时后 d 维来自不含阵亡输入列的整盘线性投影。

## 7. 与动作输出的关系

2d 维因果 Transformer 的隐藏状态产生当前策略上下文。起点头直接输出 129 个点位 logits；条件终点头接收上下文与选中起点的 129 维 one-hot，直接输出终点 logits。二人模式只取前 60 个点，两个阶段均使用裁判的合法动作 mask。动作头不再依赖逐点神经特征。输出动作仍遵循：

$$
\pi(a\mid I)=\pi^{src}(u\mid I)\pi^{dst}(v\mid I,u).
$$

输入 token 宽度不改变 `(from_code,to_code)` 动作编号，也不改变合法动作 mask。

## 8. 必须保持的不变量

1. 四国棋盘链长度恒为 129，二人棋盘链长度恒为 60。
2. 每个位置恰有一个整数码，允许码集合由信息模式和该观察者已经确定的身份共同决定。
3. 精确身份码严格为 `base + 32 × relative_seat_block`；工兵四块必须是 `32/64/96/128`，48 个精确类别不得碰撞。
4. 身份未知时四暗盟友使用 `2`；二人敌方也使用 `2`，二者由游戏模式区分；身份确定后两者都使用对家精确块 `94..105`。
5. 棋盘整数码按类别展开为整盘向量，只做一次整盘线性投影，不按数值距离解释。
6. 初始 token 为 `[zeros(d), board_embedding(d)]`。
7. 转移 token 为 `[action_embedding(d), post_action_board_embedding(d)]`。
8. 初始 token 永久保留，转移上下文最多 1,000 步，总时序长度最多 1,001。
9. 任一不可见真实身份变化都不得改变该玩家的棋盘链、动作公开字段、合法 mask 或 logits。
10. learner 保存并重编码原始棋盘链，不能使用由旧模型预计算且已过期的棋盘 embedding。
11. 开启态的已确定身份必须随存活棋子移动并写入所有后续棋盘快照；截断动作历史或恢复检查点不得清除它。
12. 开启态阵亡矩阵只保存确定死亡身份，槽位顺序必须与布局固定棋子序列相同；四暗/双明/二人的原始长度必须分别为 75/50/25。
13. 开启态双明只向模型提供两名敌方的阵亡行，并在自己与对家盟友之间共享确定知识；任何不唯一推断不得置 1。
14. 开启态把规范化 75 位阵亡向量拼入整盘投影的输入；关闭态必须令阵亡记录和张量为 `None`，且投影中不得保留这 75 个输入列。
15. 同一模式的死规则开启/关闭态都保持 2d 维、最大长度 1,001；检查点必须保存并校验模型维度与 `dead_rules_enabled`，不得交叉加载。
